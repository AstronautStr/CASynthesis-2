# 2026-09-23 — стартовая нота защёлкнута при тёмном HOLD; HOLD по умолчанию

**Баг (пользователь):** открыл `gol_synth` — нота не кончается, хотя HOLD в UI выключен;
после смены ноты поведение становится таким, как настроено.

**Причина:** `state['gate']` стартовал `True` безусловно («поле звучит сразу»), а у стартовой
ноты нет держателя (клавиша / мышь / MIDI / файл). `_release_gate()` зовётся только когда
держатель отпускает — значит стартовая нота не опускалась никогда, при любом HOLD.

**Фикс (`dd5d507`):** гейт стартует там же, где HOLD: `gate=VOICE_HOLD_DEFAULT`,
`voice_hold=VOICE_HOLD_DEFAULT` (константа в `gol_synth.py` рядом с `DEFAULT_ENGINE`).
Проба `tests/ui_articulation_probe.py` получила кейс «opening»: открыть с тёмным HOLD
(драйвер подменяет `gol_synth.VOICE_HOLD_DEFAULT` до `main()`) и ничего не нажимать — тишина.
Без фикса: rms 64 при сыгранной ноте 40 → WRONG; с фиксом 0.0 → ok.

**Затем (решение пользователя):** `VOICE_HOLD_DEFAULT = True` — синт открывается звучащим и
с горящим HOLD, как раньше, но теперь это честно видно в UI и снимается кликом. Пробы кликают
HOLD, только если нужное состояние отличается от дефолта.

**Гейты:** всё зелёное, кроме двух известных красных: `ui frame` (эталон устарел; теперь ещё и
горящий HOLD — не блессил по решению 2026-09-22) и `live budget` (Ev+FM, `gol_synth` не трогает).
