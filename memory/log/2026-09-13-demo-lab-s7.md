# 2026-09-13 — Demo lab S7: catalog check after a code change, report, saved / recomputed listening

REQ: `memory/req-demo-lab-s7.md`.

## What was built
- **`Catalog.recompute(rid)`** (`casynth_lab/catalog.py`) — the journal replay extracted
  from `replay()`: start conditions (embedded scene, or the origin snapshot of a branch) +
  recorded commands with the current code → PCM of the saved window for A / B / monitor,
  no files written. `replay()` (S4 single check, `<record>/replay/*.wav`, byte-exact bools)
  is now a thin wrapper; S4/S5 tests unchanged and green. `read_wav(with_info=True)`
  returns the stored format (SR / channels) so an incomparable pair is refused explicitly.
- **`casynth_lab/verify.py`** — the catalog check. `compare_pcm(ref, new)` classifies a
  track (`exact` | `differs`) with diagnostics over the common prefix (share of differing
  frames, max |d| in int32 — no int16 overflow; a length mismatch is `differs` by itself,
  the tail is never cut). `Verifier(catalog)`: `run()` checks every record listed at start
  (catalog order), one target = the process provenance (S6 `prov.current()`), fingerprints
  the runtime set before AND after every record (a change → `stopped`: finished results
  kept, the unfinished record + the rest `unchecked` with the reason); `cancel()` per block
  (in-process) or worker terminate (`run_in_subprocess`, `python -m casynth_lab.verify run
  ROOT`, JSON lines: `run_id` first, `record` / `progress` / `done`, `final` last; the
  parent finalises a cancelled / crashed run). Per record: origin (commit / digest / status
  of the record), input fingerprints (record.json, WAVs, snapshot files; unknown = None),
  per-track result `exact | differs | failed | unchecked` + reason, `ref_sha256` of the
  original PCM, and for differing tracks the recomputed WAV in
  `<catalog>/.verify/<run>/<record>/<track>.wav` + its sha. Record status = differs > failed
  > unchecked > exact (a partial failure keeps the other tracks' results). Reports:
  `run.json` (rewritten after every record, atomic), `marks.json` (listening marks
  `same` / `different`, only for a track that HAS a pair; cleared with None), `Run`
  view (`groups()`, `counts()`, `default_track()` = changed monitor else first changed
  A/B, `status` reads a `running` report of a dead process as `interrupted`).
  `pair(run, rid, track)` re-reads both WAVs and refuses a pair whose original or
  recomputed file no longer matches the stored fingerprints.
- **Pair player** (`casynth_lab/audio_out.py`): `play_pair(saved, recomputed, which, pos)`
  + `switch_version()` on ONE cursor (never a restart), 10 ms linear fade inside the
  player only, unity gain, the shorter version is silence after its end, playback ends
  with the longer one; the live synth is drained, never mixed in (as in S4).
- **UI** (`demo_bench.py`): catalog header buttons **Check catalog** (→ **Cancel check**
  while running; progress "N of M: title", target label) and **Last report**; every other
  catalog action is "busy" during a check; a single check refuses to start meanwhile and
  vice versa. New mode `report`: header (run id, status, target version, `< older` /
  `newer >`), group tabs Differs / Exact / Failed / Unchecked with counts, list of the group,
  card: title, origin, three track lines, track buttons A / B / As heard (keeps the
  position), version buttons Saved / Recomputed (Space toggles), Play / Stop + position,
  listening mark Can't hear / Hear it / Not rated (differing tracks only), Details
  (n_ref / n_new / % / max per track). An exact track plays the original for both
  versions (fingerprint-checked); failed / unchecked tracks play the saved WAV only. On
  window exit a running worker is cancelled and its report closed as cancelled.
- **Tests** `tests/test_demo_lab_s7.py` (6, `check.py` gate 1f; isolated repos under
  `artifacts/_s7/`) — see `tests/README.md` §4c. The test sessions are PACED (an unpaced
  sink render runs seconds ahead and "start" lands late — the same lesson as S4/S5).
- **Demo catalog** `tests/s7_demo_catalog.py` → `lab_catalog/s7_demo/`: "S7 exact" (this
  code), "S7 differs" (a child process on an isolated throwaway copy of the runtime set

  are untouched. Open: `run_demo_bench.bat --catalog lab_catalog\s7_demo`.
- Docs: `demos/README.md` S7 section, `tests/README.md` §4c, `check.py` gate list.

## Notes / limits
- One check per bench process is enforced; two benches on the same catalog could still
  run two workers (not required by S7). A report left `running` by a killed process shows
  as `interrupted` (pending = unchecked) and is not resumed.
- The runtime-set change detection re-hashes the files on disk (the imported modules
  cannot change mid-process); the conservative rule from the REQ is what is implemented.
- Reports of `lab_catalog/local/.verify/` are user data (gitignored with the catalog).
- The recomputed WAVs are stored only for differing tracks; an exact track is proven by
  the original's fingerprint.
