## Что изменено

1. **Самые долгие гейты первыми.** Пул брал список как записан, и двухминутные гейты (S7, стенд
   S1–S3, пробы прототипа) стартовали последними — волна ждала одного отставшего. Симуляция по
   измеренным длительностям: 205 с (как было) против 154 с (длинные первыми) на тех же 6 процессах,
   нижняя граница 153. Порядок берётся из времён прошлого прогона (`artifacts/gate_times.json`,
   пишется в конце каждого полного прогона), до первого прогона — из оценок `EXPECT_S`.
2. **Пауза «остыть» по делу.** `COOLDOWN_S = 6` спалось перед каждым из 9 тайминговых гейтов
   (54 с сна), включая секундные (N2 0.7 с, N3 0.7 с). Теперь — перед первым и после гейта, который
   бежал дольше `COOLDOWN_AFTER_S = 2` с; тепловой аргумент (2.96 против 5.6 мс после минуты
   плотной арифметики) для тяжёлых гейтов сохранён.
3. **`OPENBLAS_NUM_THREADS=2` у процессов параллельной волны** (дочерние стенды и воркеры
   наследуют). Первый прогон с новым порядком уронил S7 и S/N: `OpenBLAS error: Memory allocation
   still failed after 10 retries` в дочерних процессах — то же, что аудит покрытия видел днём
   (S7, articulation). Физической памяти оставалось ≥ 4.1 ГБ; упирался лимит выделения: OpenBLAS
   при загрузке резервирует буферы на все 20 ядер в каждом из ~15 процессов волны. Тайминговая
   волна оставлена на машинном дефолте — она меряет инструмент как он играется.
   Звук не зависит: `golden_master`, `events_master`, `tail_pool_master` проходят побайтно при
   1 и при 2 потоках; полный прогон — все байтовые гейты (записи каталогов, S1-хэш, якоря
   Laplace+) зелёные.

## Тиры: `check.py` по изменённым файлам, `--all` перед коммитом (тот же день)

Пользователь: «какой следующий большой шаг?» — ответ: гонять не всё на каждую правку.
Реализовано в `check.py`, тесты не тронуты:

- `python check.py` (дефолт) = быстрый набор (`fast=True`) + гейты, которые задевают файлы,
  изменённые относительно HEAD (`git status --porcelain`, staged + unstaged + untracked).
  Выбор — карта в `check.py` (`CORE_FILES` → всё; `ENGINE_GATES` → гейты закона + `EVERY_ENGINE`
  (шов, GEN, стенд S1–S3, потому что они обходят все движки); `LAB_GATES`, `ROOT_GATES`) плюс
  поиск имени изменённого файла в тексте скриптов гейтов без комментариев (сцена, сборщик,
  эталон, модуль-помощник тестов). Запись каталога опытов не запускает НИЧЕГО: это данные
  слушателя, не код. Для этого четыре теста (decay, birth strength, objects_laplace, N4)
  переписаны с «все записи в папке каталога, и их ровно N» на явные id поставленных записей —
  как уже было в тесте FM. Раньше Continue, сохранённый в такой каталог, ронял тест на счётчике,
  и первая версия карты гоняла тесты движка из-за опытов пользователя. Движки — только по карте: имя движка всплывает
  в чужих тестах случайно («5 rows since laplace_fm»). Незнакомый файл → всё, с пометкой.
  `memory/`, `docs/`, `*.md`, `*.bat` и т. п. → ни одного гейта. UI-кадр — когда задет прототип.
- `python check.py --all` = всё (прежнее поведение), обязателен перед коммитом; времена гейтов
  для порядка волны пишутся только из него.
- `--dry-run` печатает выбор и ничего не запускает; `--files=a,b` и `--since=REV`
  переопределяют «изменённое». Тайминговые тесты выбранных гейтов бегут по одному, как в `--all`.
