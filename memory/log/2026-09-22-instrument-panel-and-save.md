# 2026-09-22 — Инструмент: своя стартовая позиция, диапазоны у ручек, Save как опыт

Четыре запроса пользователя за одну сессию (после [бюджета блока](2026-09-21-render-budget.md)):
Laplace+ движком по умолчанию; те же настройки спектра «всем лапласам»; баг с невидимой
ручкой `dyn`; поля Min/Max у слайдеров; и сохранение сессии как «опыта» для стенда.
Отдельная просьба: **следить за реюзом кода**.

## 1. Инструмент открывается на Laplace+ и на настройках игрока

`DEFAULT_ENGINE = 'laplace_unified'` + `START_SPECTRUM` (n 20, spread 1, alpha 0, shape 1,
harm 1, full on, dyn 1) в `gol_synth.py`. `START_SPECTRUM` накладывается на дефолты реестра
для КАЖДОГО движка, у которого есть все семь лапласовых настроек (`laplacian`,
`laplace_carriers`, `laplace_fm`, `laplace_unified`, `ca_object_resonators`).

**Почему не в реестре.** Сначала поменял дефолты в `casynth_core.ENGINES['laplacian']` — упали
шесть гейтов: `demos/build_objects_laplace.py` утверждает `SPECTRUM == laplace_settings({})`
(«таблица ТЗ равна дефолтам реестра»), гейт закона считает моды при дефолтном n («16 != 12»),
golden master рендерит «то, что реестр называет дефолтом». То есть дефолты реестра — это
НЕЙТРАЛЬНАЯ ТОЧКА, относительно которой написаны чужие гейты и ТЗ. Откатил; стартовая позиция
живёт в инструменте.

**Цена настроек (важно для слуха и для бюджета):** n=20 вместо 12 примерно удваивает работу.
Живьём на Random-поле: Laplace+ Bank/Sine 2.8 → **5.25 мс** (0 андерранов),
Bank/Saw 3.5 → **8.34** (28), FM 4.65 → **9.58** (284) при бюджете 7.98. То есть Sine держится,
Saw и FM с этими настройками снова за бюджетом. Побитовый резерв выбран (см. лог 09-21);
дальше — либо n поменьше, либо размен бит.

## 2. Панель следует за ручками (баг `dyn`)

Симптом пользователя: «на вкладке Laplace+ первый раз ручки dyn не видно, надо перещёлкнуть
artic». Причина: `laplace_unified.inactive` прячет `dyn`, пока `shape == 0`, а панель
перестраивалась ТОЛЬКО при смене вкладки или клике по кнопочному ряду (`set_ctrl` → `rebuild_ctrls`
для choices/toggle). Слайдер `shape` менял набор скрытых рядов молча.

Правка: `set_ctrl` сравнивает набор `spec.inactive(params)` с прежним и перестраивает панель.
Безопасно под курсором: порядок рядов ставит настройку ВЫШЕ того, что она решает, а драг держит
id ряда, а не сам ряд.

Гейт `tests/ui_panel_probe.py` (в `check.py` как 3e): гоняет реальный прототип, тянет `shape`
в 0 и обратно и читает, какие ряды панель построила — через новый тестовый хук
`CASYNTH_PANEL_LOG` (как `CASYNTH_DUMPFRAME`). Проверено, что без правки гейт падает.

## 3. У каждого слайдера — поля Min/Max

Выбор пользователя из трёх макетов: поля по бокам трека, всегда видны. Ряд стал
`метка | MIN | трек | MAX`, а ЗНАЧЕНИЕ переехало внутрь трека (правый край, на затемнённой
подложке — иначе не читается на заливке): два поля съедают 74 px из 218 в колонке A.
Колонка A: 44 + 34 + 96 + 34; колонка B: 34 + 34 + 52 + 34. Длинная метка клипается по колонке.

Поведение: левый клик — ввод (текст сразу выделен), Enter/Tab — применить, Esc — отменить,
клик мимо — применить, правый клик — вернуть полный диапазон реестра. Отклонённый диапазон
(не число, за границами спеки, min ≥ max) оставляет поле обведённым и прежний размах в силе —
опечатка не двигает ручку. Диапазон НЕ трогает значение: значение вне диапазона садится на край
трека (правило стенда).

**Реюз** (по просьбе):
- `casynth_lab/textedit.py` → `casynth_textedit.py` + шим (прототипу нельзя импортировать стенд).
  Один `TextEdit` на оба UI: каретка, выделение, Ctrl+A/C/V/X.
- `casynth_panel.range_text` — одно решение, как пишется конец диапазона; читают прототип,
  рисовалка и лог панели.
- `panel_rows` уже носил `ranges` для «ranged» ручек стенда — теперь принимает их для любого
  слайдера и отдаёт `bound_lo/bound_hi` (размах против границ).
- `registry.slider_range` — арифметика проверки, которую делал `validate_range`; правило «а
  объявлен ли у параметра user-range» осталось сверху для стенда.
- `casynth_textedit.py` добавлен в `provenance.RUNTIME_FILES` (S6 поймал, что изолированная
  копия версии не стартует). В «звуковой набор» он не входит — записи не перепиниваются.

## 4. Save: сыгранное становится опытом каталога

Кнопка **Save** в тулбаре. Путь целиком из существующего кода:
`_dump_session` (сессия, которую прототип теперь пишет ВСЕГДА) → `scene_from_session` (та самая
конверсия, уже доказанная байт-в-байт против живого прогона) → **`casynth_lab.offline_record.record`**
→ `Catalog.save`. Запись неотличима от стендовой: сцена, WAV, снимок конца для Continue, пин на
коммит; `verify` реплеит её тем же путём.

`offline_record` — вынесенная общая функция: она была скопирована в `demos/build_sn_demos.py` и
`demos/build_n1_demos.py`, теперь обе зовут её (третьим потребителем стал Save). В
`SOUND_EXCLUDE`, поэтому отпечаток звукового набора не меняется.

Запись сессии теперь идёт всегда, но **аудио-чанки** (WAV живого прогона) по-прежнему только при
`CASYNTH_RECORD=1` — это то, что ест память; Save рендерит сцену оффлайн и поэтому неуязвим к
просадкам CPU. `CASYNTH_NO_RECORD=1` выключает журнал совсем. Стенд импортируется ЛЕНИВО, внутри
обработчика: без стенда инструмент играет, просто не умеет сохранять опыт.

Ограничение (по природе сцены): сессия должна держать ОДИН движок — при смене вкладки
`scene_from_session` отказывается, и Save честно говорит об этом строкой в тулбаре.

Гейт `tests/ui_save_probe.py` (в `check.py` как 3f): играет, жмёт Save и спрашивает у САМОГО
стенда — есть ли запись в каталоге, реплеится ли она байт-в-байт (`status == 'match'`) и можно ли
её продолжить.
