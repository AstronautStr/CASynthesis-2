## Что сделано (четыре коммита + чекпойнт)

0. **Чекпойнт** `6964da4` — незакоммиченная ревизия N1 предыдущих сессий (`gutter_controls.py`,
   `build_n1_hypotheses.py`, тесты, память, obsidian) закоммичена как есть, чтобы N2 не стекался
   поверх незакоммиченного (правило «сначала коммит»). Не закоммичены: `.agents/` (симлинк),
   `.claude/skills/{council,grill-me}/` — пользовательские инструменты, не проект.
1. `ca18761` **Сторона А.** `casynth_lab/periodic_readout.py` — веса `K_i` ТЗ (8 перекрывающихся
   raised-cosine, сумма 1 с ошибкой 4·10⁻¹⁶, непрерывны на торе; центры узлов; оверлей без границ).
   `casynth_lab/gutter_field_periodic.py` — подкласс `GutterFieldEngine`: заменены только
   `_set_grid` (`n_i = Σ K_i·G`, дробные) и `_eff` (trim 10^(−16.5/20) после ×20); всё остальное N1
   (источник, маршруты R1, состояния, ручки, snapshot); `model_version=gutter_field_periodic_n2_v1`.
2. `861b58f` **Сторона Б.** `casynth_lab/event_network.py` — новая модель по формулам ТЗ, numba-ядро
   в порядке операций ТЗ (возбуждение → затухание импульсных состояний → чтение ВСЕХ задержек и
   фильтров → запись новых значений). Кольцевые буферы (8, 1361) с длинами `D_i`, счётчик `k`,
   матрица `M` явная (8×8, суммирование j=0..7), панорама cos/sin по `p_i`, выход /8 → ×96 → gain
   стенда с косинусной рампой как у N1. Ручка `rho` («Response» 0.60…0.95): линейная рампа 882
   отсчётов на семпл-пути, состояние рампы в snapshot. События на границе блока в `render_float`
   (`_events()`): `E = (G != G_prev)`, `a = e/(e+2)`, `G_prev = copy(G)`; `update_field` только
   запоминает ожидающее поле; `exc` игнорируется; init/reset — нули и `G_prev=0` (один начальный
   пакет); restore восстанавливает `grid_prev`/`grid_pending` и проверяет, что ожидающее поле
   совпадает со стендовым (иначе ValueError) — пакета не добавляет. Только SR 44100/блок 352/стерео.
   `raw_block(events=…)`, `inject(a)` — проверочные хуки.
3. `9e40aba` **Стенд + материал.** `demo_bench.py`: ветка `_draw_display` для ключа `events`
   (бары `a_i`, тик `max|l_i|`×4, rho и рампа); обе стороны N2 рисуют оверлей центров узлов + кольцо
   полувеса (жёстких прямоугольников N1 нет). Реестр: 13 движков → 5 рядов кнопок (проверено:
   до подвала панели остаётся 60 px; тесты S/N и N1 обновлены). `demos/build_n2_events.py` —
   три сцены/записи по ТЗ (клетки сверены с preflight-JSON), гипотезы ТЗ в Notes дословно,
   `run_network_n2.bat`. Каталог собран: `lab_catalog/network_n2_events_2026_09_16/` (3 записи,
   clip 0/0, все реплеятся `match`).
4. (этот коммит) **Измерения + память.** `demos/n2_events_report.py` →
   `demos/results/network_n2/report.{json,md}`; `memory/current.md`, `questions.md`, этот лог.

Тесты `tests/test_n2_events.py` — 19, гейт 1j в `check.py`:
- ядро Б == независимый скалярный референс формул ТЗ **побитово** (одиночный и перекрывающиеся
  пакеты, сквозь рампу rho с посэмпловым массивом rho);
- события: рождение и смерть складываются (нет взаимоуничтожения), неизменное поле — 0,
  правки внутри блока сливаются (возврат к прежнему полю — без события), параметры — не событие,
  reset = один пакет, `exc` игнорируется;
- причинность по состояниям `l_i`: импульс в узле `i` виден на его выходе ровно через `D_i`,
  в узле `j` — через `D_i + D_j` (проверено для i=0 и i=5 против референса);
- нулевое состояние без событий остаётся ровно 0; хвост монотонно затухает (< −100 dBFS через 12 с);
- snapshot: сохранение/загрузка через `snapshot.py` посреди рампы, продолжение побитово, restore не
  добавляет пакет, отказ при чужом поле/версии;
- перенос одного и того же события между узлами меняет огибающую и спектр после выравнивания энергии;
  стереообраз до прихода связей следует `p_i`;
- лимиты при gain 0.04 (vol 1): полный toggle и случайное поле каждый блок при rho 0.60/0.95 —
  без клипа и NaN; отказ при SR 48000 / блоке 256; тайминг движка p99 < 4 мс;
- сторона А: веса против формул ТЗ, периодичность на торе (сдвиг на шаг узла = соседний узел),
  сырой выход на пустом поле == `gutter_field`, trim точно −16.5 dB, клетка внутри области N1
  меняет счёт, snapshot посреди рампы Links;
- стенд headless: оверлеи/панель обеих сторон, выбор Б; сцены: периоды pulsar 3 / glider 128,
  4 события/шаг, R-pentomino 71/66 на 72-м поколении; каталог: сборка, точный реплей, Continue
  побитово с продолжающейся эволюцией, Notes с гипотезой, защита от перезаписи.

## Измерения (`demos/results/network_n2/report.md`)

- Сцены 2–12 с (моно RMS): А −37.1 / −36.9 / −36.4 dBFS, Б −35.4 / −39.7 / −35.2 dBFS — совпадают
  с preflight Researcher до 0.1 dB; стереопики Б 0.132 / 0.129 / 0.159 (preflight те же). Клипов
  и reset'ов нет. p99 обеих сторон 0.5–0.7 мс при бюджете 7.98 мс.
- Хвост Б после паузы КА (float): −56…−58 dBFS через 1 с, −118…−120 dBFS через 2 с.
- Continue из конечного состояния: КА идёт дальше (25/65/25 поколений за 4 с), обе стороны звучат.
  Поздняя правка (перенос поля на полтора ряда узлов) против продолжения без правки: обе стороны
  во всех сценах отличаются (лог-спектральная дистанция 5–10 dB на А и 7–9 dB на Б, окно 0–3 с).
- Перенос одного события между узлами (Б, энергия выровнена, 1 с): корреляция огибающих 0.61–0.98,
  лог-спектральная дистанция 5.2–5.5 dB RMS; численный неноль, слышимость не доказана (ТЗ).
- Лимиты при gain 0.04: плотное случайное поле, случайное поле каждый блок, повторные ручные
  правки на паузе, rho 0.60/0.95 — без клипа/NaN/reset; пик Б 0.965 при rho 0.95 и случайном поле
  каждый блок. Проба «всё поле каждый блок»: пик Б 0.969 (preflight 0.972), клипа нет; **на А
  ~9·10⁵ reset'ов узлов** — идентично исходному N1 `gutter_field` (1044547), при переключении раз в
  4 блока — 0. Это NaN-защита узла Gutter под 125-Гц перестроем, недостижимым руками/КА;
  вынесено в `questions.md` как наблюдение, модель А не менялась.
- Полевые траектории (gen, население, пакет `a_i` по узлам на каждый блок; события по узлам на шаг)
  сохранены в `report.json`.

## Отклонения / решения
- Оверлей: кольцо радиуса 4 клетки = полувес по горизонтали (эллипс стенд не рисует); центры узлов
  на полуцелых координатах (3.5, 7.5) … (27.5, 23.5).
- Метки движков в реестре — короткие ASCII (`Gutter K`, `Events`); имена сторон ТЗ («А — поле
  меняет частоты», «Б — события возбуждают сеть») — в описании записи и строке `listen` сцены.
- `display()` А отдаёт дробные `counts` (панель показывает как есть).
- Хвост/сравнения Б в отчёте измерены по float-выходу: int16 квантует ниже −90 dBFS в ноль.
