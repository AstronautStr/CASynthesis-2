# 2026-09-15 — N0: воспроизведение звукового референса Gutter Synthesis

ТЗ: `memory/req-network-reference-n0-2026-09-15.md`. Поставка: `demos/results/network_reference_n0/`
(README + manifest + три примера + пробы). Код: `demos/network_reference_n0/`. Коммиты: `2d1b957`
(порт + сверка + движок + тесты), следующий — рендер пакета и память.

## Четыре ответа, которые требует ТЗ

1. **Реализован ли референс?** Узел — да, побитово: исполняемый `gutterOsc.class` из репозитория
   автора запущен на JVM (портативный JDK 17 в scratchpad, две заглушки Max-API) на одних входных
   массивах с Python-портом; 14 случаев (все шесть режимов дисторшна, фильтры выкл, 12 фильтров,
   сообщения во время DSP, вход audio, HP включён, блоки 1/64/512) — float32-выходы и трассы
   состояний совпадают точно (режим 5 через `Math.exp` — интринсик HotSpot — расходится на 1 ulp,
   в патче не используется). Сеть — транскрипция Max-патча (`matrix~ 8 8` пресет 1 → `delay~` →
   ×interaction → в **демпфирование** `c` узла; выход узла через `clip~`/`svf~ 20`/`svf~ 30`/
   `tanh~`/pan). Max не запускался; четыре допущения вынесены в `questions.md` (векторная
   задержка feedback 64, `delay~` 2000 вместо random(2000..3999), формула `svf~`, порядок
   восстановления слайдеров при загрузке). Все — константы `config.json`.
2. **Найдено ли техническое разнообразие?** Да, по измерениям. Пробы (одна ось, 5 значений,
   вмешательство на 4-й с, окно 6–12 с, контроль без вмешательства): демпфирование 40/90 →
   центроид ×0.07 (линии резонаторов → низкий рокот ~60 Гц, +2…4 дБ); демпфирование 190–256 →
   спектр чище (log-spectral distance 3–6 дБ при том же уровне и центроиде); interaction 190–256 →
   центроид ×0.12…0.34, +2…3 дБ, рост модуляции огибающей (медленное «дыхание»); mod 92 →
   −5 дБ, центроид ×0.32, +3.5 дБ std огибающей; mod 138/184 → система схлопывается в тишину
   (−52…−58 дБ); mod 0/23 после запуска почти ничего не меняет (система самоподдерживается),
   но из нулевого состояния mod 0 = тишина (звук возбуждается только вынуждающей силой; её
   период при исходных параметрах ≈ 26 с, т. е. это медленный толчок, а тон рождается в
   обратной связи резонаторы↔Дуффинг). Связи вкл/выкл при исходном interaction 127: уровень и
   временное поведение те же, спектральный состав другой (LSD ≈ 10 дБ, flatness −63 → −49 дБ);
   при interaction 230 — явная смена характера. PCM-разность везде > 0 дБ (траектории
   расходятся) — как и предупреждало ТЗ, сама по себе не показатель.
   **Гистерезис:** в `02_control` после возврата damp 40 → 138 на 8-й с система НЕ возвращается
   к линейчатой текстуре — рокот остаётся до конца (центроид 65 Гц против 898 Гц у контроля),
   хотя те же параметры из нулевого состояния дают текстуру A. Это свойство нелинейной системы
   (разные аттракторы), важно для N1: управление зависит от истории.
3. **Проверял ли кто-либо звук на слух?** Нет. Агент не может слушать; все утверждения выше —
   измерения и спектрограммы (`figures/`). README не использует слово «слышно» как факт.
4. **Можно ли переходить к КА?** Технически материал для решения есть: три оси дают разные
   измеримые типы изменений (уровень / спектр / временное поведение). Решение — за Researcher
   после короткого прослушивания пользователем (`req-listen-network-reference-n0-2026-09-15.md`).
   Оговорки: (а) неопределённости Max-обвязки выше; (б) исходная «конфигурация» источника
   случайна при каждой загрузке (фильтры, задержка, пресет движения) — зафиксирована seed-ом
   и константами; (в) сильная вынуждающая сила гасит систему — для N1 диапазон mod ограничен
   сверху (~92).

## Что сделано (как)

- Разбор патчей скриптами по JSON (`boxes`/`lines`, порядок inlet-ов по x): найдено, что узлы —
  восемь `bpatcher mxjGutterCompact.maxpat #1..8`; связи — `p matrix`; инициализация —
  `autopattr restore` (gain 162, damp 138, mod 46, rate 39, Q 149, soften 103, interaction 127,
  filter_count 24) + `loadmess` (setHighpass 5, omega 0.002, pitch_shift 1.0) + случайные фильтры
  (`p randomise_filters_mixed_root`, формула воспроизведена, seed 20260915).
- Ключевая находка: **патч исполняет `gutterOsc.class`, скомпилированный не из `gutterOsc.java`**
  (6 входов и один банк против 8 входов и двух банков; `javap`/CFR). Портирован байткод.
- Побитовость потребовала порта fdlibm `atan` (`jmath.py`): `math.atan` C-runtime отличается на
  1 ulp в ~0.6 % значений, чего хватает для расхождения хаотической системы.
- Движок: numpy по 8 узлам, ~52 мкс/отсчёт (2.3× медленнее реального времени); пробы —
  параллельно (16 процессов, ~1 мин), примеры — ~4 мин. Состояние экспортируется/восстанавливается
  байт-в-байт (тест), разбиение на блоки не влияет (тест).
- Уровень: один коэффициент `MASTER_GAIN = 0.85` на все файлы; пик 0.719 (−2.9 dBFS), клиппинга нет.
- Воспроизводимость: два полных запуска (16 и 8 воркеров проб) дали побайтово одинаковые
  float-файлы (sha256 в manifest); разбиение на блоки и продолжение из состояния — тесты.
- Дополнительный файл `03b_links_strong.wav` (interaction 230, явно помечен как экстра) —
  пара OFF/ON при сильной связи, где сеть меняет характер, а не только спектральный состав.
- Гейты: `python check.py` — все PASS, кроме S6 при одновременном рендере 16 проб (нагрузка);
  отдельно S6 7/7. Новый гейт 1h: `tests/test_network_reference_n0.py` (9 тестов, ~2 с).

## Известные ограничения / что не делалось

- Max-объекты (`svf~`, `line~`, `matrix~`, `delay~`, `cycle~`-pan) — транскрипция, не исполнение.
- Пресет движения SLOW и рассылка мастер-слайдеров главного патча при загрузке не применены
  (см. questions); банки фильтров `filters.txt` (Bell/Porcelain/Piano/Choir/Organ) доступны
  через `default_config(filter_bank=<idx>)`, в поставке не использованы.
- Живой адаптер стенда, интеграция с КА, оптимизация — вне N0.
