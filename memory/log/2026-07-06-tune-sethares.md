## Цель
Магнит note-on несущей к минимумам кривой диссонанса Пломпа–Левельта, вычисленной из
суммарного спектра колонии. Обратный конец оси `harm`: подгонять музыку под существо.
Дизайн: `decisions.md` 2026-07-05 «Строй существа (Сетхарес)»; REQ — `questions.md`.

## Что изменено

### `casynth_tuning.py` (НОВЫЙ модуль; numpy, без pygame)
- Константы: `TUNE_CURVE_STEPS=1300` (~1¢/шаг на [1, 2.1]), `TUNE_MAX_PARTIALS=24`,
  `TUNE_SKIP_BELOW=1.02`.
- `pair_dissonance(f1,a1,f2,a2)` — Пломп–Левельт, паритет с
  `frontiers_explainer/src/linalg.js:130-134` (те же константы 0.24/0.021/19/3.5/5.75,
  взвешивание `min(a1,a2)`).
- `dissonance_curve(freqs, amps, r_min=1.0, r_max=2.1, steps)` — суммарный диссонанс
  объединённого спектра {S, r·S}. Векторизация разложением на 3 группы пар (эквивалент
  верхнего треугольника 2N×2N как в JS): SS-пары (константа, один раз), rS·rS-пары
  ((P,R)-broadcast), кросс-пары S×rS ((N,N,R)-broadcast). ~30 МБ пик при N=24 —
  приемлемо для one-shot на note-on (≈1–10 мс).
- `scale_minima(curve, ratios, skip_below)` — ВСЕ внутренние локальные минимумы
  (JS-потолок 6 не перенесён — прагматика дисплея стенда), нестрогое сравнение соседей
  + порог глубины 1e-6; область r ≤ skip_below пропускается (унисонная яма).
- `snap_ratio(r_raw, minima, tune)` — октавная свёртка `k=floor(log2(r))`, r/2^k ∈ [1,2);
  ближайший минимум по |Δ центов|; геометрическая интерполяция
  `r·(r_min/r)^tune` (= линейная в центах); разворот `·2^k`. Гард: свёрнутое r ниже
  `TUNE_SKIP_BELOW` (точные октавы/унисоны) — без снапа. tune≤0 / нет минимумов /
  r≤0 → прозрачно.

### `gol_synth.py`
- `state['tune']` (0..1, дефолт 0) + `state['tuned_f0']` (float Hz — фактическая
  звучащая несущая; преднасеяна `midi_to_freq(NOTE_DEFAULT)`).
- `_snap_note_on(new_note)`: одна точка снапа. Спектр колонии = все партиалы живых
  голосов из `render_spec['cur']`, рескейл `base_f0 → prev_f0` (фактическая звучащая
  несущая = референс интервала), нулевые амплитуды выброшены, топ-24 по амплитуде
  (`argpartition`); кривая → минимумы → `tuned_f0 = prev_f0 · snap_ratio(f_raw/prev_f0)`.
  Прозрачные пути: tune=0 (референс освежается), нет référence, пустое поле/голоса.
- Детект note-on: поллинг `state['note']` в main-цикле (≤1 кадр латентности — допущено
  REQ п.4), покрывает все три пути входа (MIDI/экранное пианино/клавиатура) одной точкой;
  каждый note-on снапается ровно один раз.
- `_live_voices`: при tune>0 рескейл голосов к `tuned_f0`; при tune=0 — прежний путь
  `midi_to_freq(note)` бит-в-бит.
- UI: ручка `T` — 5-я строка ENV-блока (synth-wide, после ADSR). `TOOLBAR_H` 226→248
  (`casynth_config.py`) — UI-дамп-гейт `_ui_before.png` легитимно уедет (он и так ждал
  обновления после спектр-полоски).
- Session-лог write: `tune` + `tuned_f0` в пер-кадровый `replay_controls`.

### `casynth_session.py`
- Read-side: `f0 = c.get("tuned_f0", midi_to_freq(note))` — реплей читает ФАКТ
  (готовую несущую), не пере-выводит note-on (урок REQ dyn). Частоты линейны по f0 у

  фоллбек на `midi_to_freq(note)` бит-в-бит.

## Отклонения от ТЗ (несущественные, зафиксированы)
- Снап считается в main-цикле по поллингу ноты (≤1 кадр), а не в точке
  `note != last_note` рендер-потока — REQ явно допускал этот вариант (бюджет чанка).
- `scale_minima` принимает `(curve, ratios)` (двумя массивами) вместо структуры
  «curve» из JS — интерфейсная мелочь.
