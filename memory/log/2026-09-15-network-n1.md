## Что сделано (как)

- **R1 исправлен явно.** `GutterNetwork` получила ключ конфигурации `output_routes` ({L, R}
  маски по узлам): `R[5]=0` действует и в правом мастере, и на входе матрицы (`m_in =
  0.5·(L+R)`). Без ключа — прежнее поведение, пакет N0 воспроизводим из своего `config.json`.
- **Модель N1 = явная версия.** `casynth_lab/gutter_field_n1_config.py` — Python-литерал
  (входит в звуковой отпечаток провенанса) = `reference_config` из fixtures Researcher +
  `output_routes` + `post_math="scalar"` + `model_version="gutter_field_n1_v1"`. Тест сверяет
  его с файлом fixtures, когда файл на месте (файл — территория Researcher, не закоммичен мной).
- **Скорость: numba-ядро.** На машине нет компилятора (ни cl, ни gcc), `numba 0.67` ставится
  под Python 3.14 — добавлен в `requirements.txt`. Одна функция `_render(n, …)` на блок:
  тот же порядок операций, что у скалярного порта узла (`gutter_node.py`, сверен с JVM) и у
  `GutterNetwork.step`. Итог ~0.4–0.6 мкс/отсчёт/сторона против ~52 у N0 (per-sample numpy):
  блок обеих сторон p99 = 0.75 мс оффлайн / 2.07 мс в живом стенде при бюджете 7.98 мс.
  Без numba та же функция исполняется чистым Python (верно, тест сверяет `py_func`
  с компилятом побитово — контракции FMA нет), но не real-time.
- **Почему у модели появился `post_math="scalar"`.** Побитовая сверка ядра с numpy-моделью
  невозможна принципиально: `np.tanh` расходится с C-runtime `tanh` в последнем ulp у ~20 %
  значений (numba/`math.tanh` совпадают с C-runtime, проверено на 5·10⁵ точках), `ndarray.sum`
  суммирует попарно, `@` (BLAS) — с FMA. Для хаотической системы допуск бессмыслен, поэтому
  референс определён точно: tanh из C-runtime, суммы мастера и произведение матрицы —
  последовательно от 0.0 в порядке индексов. N0-режим (`numpy`) оставлен по умолчанию.
  (Попутно: встроенный `sum()` Python ≥ 3.12 — компенсированное суммирование, в тестах
  используется явный цикл.)
- **Поле → частоты** ровно по ТЗ: `region_bounds` (floor-границы 2×4, `i=4r+c`),
  `u=n/(n+2)`, `ratio=2^clip(log2 scale + depth(2u−1), −1, 1)`, `f=min(19000, base·ratio)`
  → float32 → `calcCoeffs`; применяется в `update_field`/`set_params` (граница блока стенда),
  состояния фильтров/узлов не трогаются, сдвиг от `base` не накапливается. Freeze CA держит
  `u_held` (init — начальное поле; off — текущее); depth=0 → ratio=scale.
- **Стенд:** новый ключ оверлея `lines` (прямые границы без тор-обёртки) + подписи 0..7 в
  центрах областей; панель `display()` для `'u'`: бар удержанного u, тик — u поля, счётчик
  клеток, ratio, links, resets. Уровень: `FIXED_SCALE=20` перед gain стенда (0.56 при
  дефолтах); пик на сцене 0.42–0.47, клипа нет.
- **Снапшот:** все массивы (узлы, 4 матрицы состояний фильтров, коэффициенты и частоты,
  6 рамп + G-рампа, кольцо 8×2065, u_held/u_field/counts/ratio, ints k/G_left) + params,
  frozen, gain_prev, model_version, delay. Continue байт-в-байт in-process и из файлов в
  свежем процессе; отклонения до замены сессии.

1. **Верность модели.** JVM-сверка узла повторена (JDK 17 и клон `guttersynthesis` из
   scratchpad сессии N0): 13 сценариев ALL PASS, хеши источника = commit `efa4737a…`.
   Направленная связь 6→4 при D=3 и 2064: первое изменение входа демпфирования ровно на
   отсчёте D, значение = независимому расчёту (ошибка 0); правый маршрут узла 6 = 0 в мастере
   и в матрице (при N0-маршрутах ≠ 0). Ядро == медленная модель байт-в-байт на статике,
   эволюции, рампе Links через границу блока, переносах поля туда-обратно, Freeze+scale/depth;
   по отсчётам ядро == модель == скалярный порт (2600 сэмплов, все состояния 8 узлов).
2. **Влияние поля.** u/counts трёх полей fixtures точно, ratio ≤ 1e-12, частоты float32
   ≤ 19 кГц. depth=0 и Freeze CA: 48 правок клеток не меняют PCM стороны B (A меняется).
   Сцена 12 с: A и B тождественны до первого шага КА, далее различаются; уровень одинаков
   (−20.4 dBFS), spectral flux A 0.019–0.023 против B 0.008–0.017. Расписание переносов
   (20 с, КА на паузе): после первого переноса центроид 2501 → 481 Гц, доля 20–100 Гц
   растёт до 0.5–0.66, при возврате поля исходный спектр НЕ возвращается (259–378 Гц на
   поздних окнах) — зависимость от истории, о которой предупреждало ревью N0, в N1 сохраняется.
   Сбросов узлов 0, клипа 0 во всех прогонах.
3. **Живая работа.** Оффлайн 60 с обеих сторон с правками/эволюцией/ручками: p50 0.42,
   p95 0.57, p99 0.75, max 2.68 мс, ни одного блока за бюджетом. Живой стенд (LiveEngine,
   sounddevice, 60 с, 7539 блоков, 63 поколения, паузы/смены стороны/ручки): **0 опустошений**,

4. **Продолжение опыта.** Тест: снепшот посреди 50-мс рампы Links и сразу после правки →

5. **Регрессия.** `python check.py` — все гейты (см. ниже); крайние ручки × поля: конечные

## Известные ограничения / заметки

- numba компилирует ядро при первом создании движка (~1–3 с, дальше кэш в `__pycache__`);
  компиляция происходит в конструкторе (до старта аудио), поэтому опустошений при старте нет.
- Оверлей/панель — только для слушаемой стороны (как у S/N).
- Скрипт отчёта в живой секции реально играет звук (vol 0.05); `--no-live` пропускает.
- Файлы Researcher (`req-network-ca-n1…`, fixtures) не коммитил — их территория.
