## Что сделано

1. **Objects v5** (`ca_object_resonators_n4_v5`, `STATE_VERSION 5`, массивы снимка те же; v4-снимок без ключа
   принимается как s = 1 побитово, v3/v2 — как прежде):
   - ручка **Birth strength** `birth_strength` 0…4 (float, default 1; отсутствие ключа = 1) сразу после Excitation;
     значение проверяется на конечность и диапазон в реестре (`validate_param`), в `set_params` (при отказе параметры
     не меняются) и в `restore_state`.
   - закон (`birth_strength_profile(b, s)`, чистая функция): s = 1 → сам b (тот же объект, без арифметики);
     0 < s < 1 → `v = (1−s) + s·b`; 1 < s ≤ 4 → `v = b^s`; `c = √m · v / ‖v‖`. В `_packet`: s = 0 → `_strike(s, e)`
     — прежний Uniform-тракт (состояния слота `zf/zs`), пространственное участие не вычисляется, но условие
     Births/Own/Laplace/full по-прежнему обязательно (s = 0 его не обходит); ноль участия при s > 0 — пакета нет
     (b = 0, смесь не применяется). Смена s не создаёт пакета и не трогает состояния ни одного из трактов.
   - `inactive()` при Uniform: `"1.00  Birth position only"` (ручка хранится, показана с числом, не редактируется);
     `display()`: `birth_strength`, `birth_strength_hint`.
2. **Стенд:** 17 строк панели Objects → `ROW_H 20→18` (`CHOICE_H 16`, `RANGE_FIELD_H 18`, чтобы кнопки и поля
   диапазона не наезжали на соседние строки); окно на столе 960 px: 872 px при 3 строках фигур (было 872 при 16
   строках и ROW_H 20). Четвёртая строка шапки Objects (`FIGURE_HEAD_H 48→62`): при Birth position —
   «0 Uniform, 1 original, >1 stronger selection» (250 px; дословная строка ТЗ «0 = Uniform; 1 = original;
   >1 = stronger selection» — 289 px — не помещается до колонки Patterns при ширине панели 270 + 16), при Uniform —
   «Birth strength 1.00 stored (Birth position only)». Текст неактивной ручки сдвинут на 6 px (подпись «Birth strength»
   81 px упирается в слайдер на 82 px).
3. **Сцены:** все 11 прежних Objects-сцен (`n4_*`, `ol_*`, `ora_*`, `oes_*`) перегенерированы сборщиками с
   `birth_strength: 1.0` (звук тот же; записи их каталогов остаются на своих коммитах — по правилу пользователя старые
   записи не подгоняются под текущий код). Новая `demos/obs_m2.json`.
4. **Каталог M2:** `demos/build_objects_birth_strength.py` → `lab_catalog/objects_birth_strength_2026_09_18/`
   (1 запись, гипотеза ТЗ 5.3 в Notes дословно), `run_objects_birth_strength.bat`. Поле — `cases.M1.cells` preflight
   2026-09-17 (Jam p3), обе стороны — настройки M1 + Births + Birth position; А s = 1 / Б s = 4. Калибровка: side_gain
   Б **0.92** (при единичных гейнах А−Б после 2 с −0.73 dB, весь дубль −0.69; старый 0.93 не переносился) → А−Б после
   2 с −0.01 dB. Пики 0.134 / 0.123 (стартовый пакет всей фигуры — b = 1 при любом s), клипа нет, общий уровень
   не снижался. В описании записи и в `listen` сказано, что ручное изменение силы может менять громкость.
5. **Отчёт:** `demos/objects_birth_strength_report.py` → `demos/results/objects_birth_strength/report.{json,md}`.

## Измерения (`demos/results/objects_birth_strength/report.md`, коммит `ecb464b`)

- **Закон:** 10 случаев preflight × 5 сил — max |c − preflight| 4.4e−16, |Σc² − m| ≤ 8.9e−16; контрольная таблица
  ТЗ (16 клеток) совпала до 6 знаков; точный ноль сохраняется при s ≥ 1 (0.526 при s = 0.5); равные b равны, одна
  мода c = 1, c ≥ 0.
- **M1 при пяти силах (72 перехода бок о бок):** частоты, веса, моменты пакетов, a и трекер равны у всех пяти
  движков; 123 пакета; коэффициенты всех фаз == preflight при каждом s (≤ 4.4e−16). При s = 0 per-mode состояния
  ровно 0 (только uniform-тракт), при s > 0 — только per-mode.
- **Тракт (PCM):** Birth position s = 0 == Uniform побитово на всей сцене M2 (12 с); Uniform при s = 4 == при s = 1;
  s = 1 vs 4 max |ΔPCM| 795. **WAV обеих записей каталога 2026-09-17 (E1, M1; сцены без ключа) == рендер текущего кода
  побитово по A/B/monitor** — s = 1 есть прежний Birth position, Uniform не изменился (прямое сравнение WAV, не реплей
  каталога: строгая валидация сцены отвергает отсутствующий ключ, и по правилу пользователя старые записи не подгоняются).
  Смена s на неподвижном поле через 0 и 1: блоки и состояния равны двойнику, счётчик изменений равен. Последовательность
  [4, 0, 0.5, 1, 2, 0] по переходам E1: каждый пакет со своим s, per-mode история при s = 0 не стирается, uniform-тракт
  получает пакет. Журнал раннера с пятью сменами ручки: Continue с 6 с 200 блоков точен (A/B/monitor); v4-снимок
  импортируется как s = 1 с тем же звуком.
- **Уровни:** сторона Б при s 0/0.5/1/2/4 с единичным гейном: RMS после 2 с −36.85/−36.44/−36.25/−36.00/−35.52 dB
  (усиление отбора монотонно поднимает уровень на ~1.3 dB от 0 до 4), пик 0.134 при всех s; с гейном 0.92 — −37.57…−36.24,
  пик 0.123, клипа нет, всё конечно. p99 блока 2.9–3.6 ms при бюджете 7.98 при всех s и при движении ручки каждую
  секунду (3.40). Continue сцены с 6 с точен; 26 хвостов к концу (распады Jam), без обрывов.
- **Каталог:** 1 запись, replay match, pinned `ecb464b`, Notes есть.
