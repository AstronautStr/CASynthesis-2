# S3 — подключение звукового движка к стенду

2026-09-09. **S3 реализован; пользователь запросил переход к S4.** Ниже — ТЗ завершённого шага; [лог реализации](log/2026-09-09-demo-lab-s3.md). Текущая задача — [S4: локальный каталог и повтор](req-demo-lab-s4.md) по [общему плану](req-demo-lab.md). Прежний Scan Memory в S3 не входит.

## Для пользователя — прочитать только это

**Результат:** движок подключается отдельным модулем с описанием параметров; стенд обеспечивает поле, запуск, A/B и запись звука. Добавление движка не требует переделывать проигрыватель и интерфейс.

Переводим на этот механизм существующий синтезатор с пятью методами. Звук и привычное управление сохраняются. Новый метод сонификации не разрабатываем. Основная приёмка автоматическая; тебе — одна короткая проверка запуска ниже.

## Поставка

1. Общий интерфейс звукового движка, используемый живым стендом и офлайн-рендером.
2. Адаптер существующего синтезатора: все пять методов доступны под прежними идентификаторами, с прежними параметрами и звуком.
3. Единый реестр стенда: идентификатор, название, параметры и способ создания экземпляра движка; из него работают UI, сцены и команды.
4. Короткая инструкция в `demos/README.md`: где добавить модуль, как зарегистрировать его и сослаться на него из JSON-демо, какие проверки запустить.

Конкретные классы и файлы выбирает Developer. Достаточно явной регистрации в одном месте; поиск плагинов по каталогам, установка пакетов и горячая загрузка не требуются. Добавление новой сцены для зарегистрированного движка — только JSON, без изменений Python.

## Граница ответственности

**Стенд** ведёт общее поле КА, часы, очередь и журнал команд, транспорт, экземпляры A/B, переключение монитора, живой вывод и WAV-рендер.

**Движок** получает полное поле, его изменения, применённые параметры и необходимый контекст расчёта: частоту дискретизации, размер блока, звуковое время, f0 и уровень. Он возвращает готовый стереоблок аудио и диагностику уровня/клиппинга. Инициализация на текущем поле, обновление входов, рендер следующего блока и сброс должны быть доступны через общий интерфейс. Сигнатуры — решение Developer.

Внешний договор не требует списка партиалов, объектной сегментации или SlotPool. Нынешние `analyse`, `SlotPool`, фазы и огибающие остаются внутри адаптера существующего синтезатора. Их расчёт переиспользуется из общей библиотеки, без копирования DSP.

Для S3 использовать нынешний формат блоков: `int16`, форма `(BLOCK, 2)`, существующие SR/BLOCK. Уровень применяется один раз; порядок вычислений и округлений старого аудиопути сохраняется. Автонормализацию и дополнительную обработку звука не вводить.

Каждая сторона имеет отдельный экземпляр движка. Обновления приходят на прежних границах блоков в порядке журнала; обе стороны вычисляются независимо от того, какую слушают. Движок не изменяет общее поле и не использует собственные настенные часы. Управление устройством остаётся в `audio_out.py`.

Текущие `SideState.analyse/render/reset_audio` — отправная точка извлечения адаптера, а не основание переписывать исполнитель целиком. Метаданные пяти методов брать из `casynth_core`, не дублировать. Основной `gol_synth.py` продолжает пользоваться общей DSP-библиотекой; переводить его на новый интерфейс в S3 не требуется.

## Сохранить принятое поведение

- Сцены JSON v1/v2 и прежние команды запуска, включая `--side A|B|monitor`, работают.
- Start, полный Stop, Restart и Pause CA сохраняют смысл S2; на паузе КА звук и рисование продолжаются.
- Выбор A/B меняет монитор с прежним переходом 20 мс, без изменения исходного аудио сторон.
- Параметры меняются только у нужной стороны; сохраняется запоминание настроек каждого метода, смена метода, копирование настроек и Factory A+B.
- Сохраняются диагностика клиппинга/underrun и режим без устройства; UI получает названия и ручки из реестра.
- `run_demo_bench.bat` по-прежнему открывает `demos/laplace_ab.json`. Новых панелей и органов управления не требуется.

## Автоматическая приёмка

1. **Звук до/после.** До рефактора сохранить результаты принятого S2 для пяти методов на фиксированной сцене и журнале с рисованием, параметрами и транспортом; после сравнить A, B и monitor байт-в-байт. Существующий эталон `demo_lab_s1_ref.sha256` сохранить. Ожидаемые результаты не получать через новый адаптер и не переблагословлять ради прохождения.
2. **Подключение.** В тесте зарегистрировать существующий адаптер под дополнительным идентификатором: сцена, валидация, UI и офлайн-рендер используют его без правок своих реализаций. Отдельная простая заглушка с заранее известным PCM проверяет, что исполнитель принимает готовое аудио без обращения к партиалам/SlotPool; она существует только в тестах и не является новым методом сонификации.
3. **Независимость и время.** Существующие сценарии S2 проходят через интерфейс: изменение B не меняет raw A, выбор монитора не меняет raw A/B, reset воспроизводим; live/offline совпадают при одинаковом применённом журнале.
4. **Ошибки и совместимость.** Неизвестный движок и неправильные параметры дают понятную ошибку; блок неправильной формы/типа не попадает в аудиовыход. В headless UI проверить прежние пять методов, их ручки и регистрацию из пункта 2.
5. **Гейты.** `python check.py` проходит с включёнными новыми проверками; старые аудио/UI-эталоны сохраняются. Короткий smoke живого запуска проверяет отсутствие новых сбоев вывода; недоступность устройства явно отметить.

Проверки соответствия интерфейсу и отсутствия изменений звука — ответственность Developer, не слуховая задача пользователя. Временные WAV/отчёты — `artifacts/`; необходимые постоянные эталоны — `tests/golden/`.

## Границы и сдача

Scan Memory, иной новый звуковой метод и специальный движок с собственной памятью в S3 не входят. Сохранение и продолжение снепшота остаются обязательной частью плана S4–S5; в этом спринте их хранение и сериализацию не реализовывать.

Сдача: готовый прежний запуск, инструкция подключения, результаты проверок и ограничения — отчёт до десяти строк. Обновить лог реализации и устаревший указатель S3 в `memory/current.md` по этому ТЗ.

**Одна ручная проверка, около минуты:** открыть `run_demo_bench.bat`, нажать Start, переключить A/B и изменить harm на B — привычное управление и звук работают. Пользователь не обязан оценивать новый тембр или проверять архитектуру.

После сдачи S3 остановиться; следующий спринт — после приёмки.
