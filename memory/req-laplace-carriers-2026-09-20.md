## 1. Задача и исследовательская развилка

Нужно проверить, расширяется ли семейство звуков при сохранении слышимой связи с геометрией и эволюцией КА. Текущий Laplacian даёт удачные формозависимые тона; событийные Objects — удачные музыкальные рисунки. По слуху пользователя оба остаются преимущественно в металлическом семействе. Изменения места/силы возбуждения и потерь не дали искомого расширения; повторять их как следующий опыт не требуется.

Два новых закона на ОДНИХ исходных лапласиановских частотах и весах:

- **Filter:** одна периодическая волна на частоте ноты для каждой фигуры; лапласиановский профиль управляет амплитудами её гармоник.
- **Wave bank:** одна периодическая волна на частоте КАЖДОЙ выбранной моды; амплитуда этой волны равна весу моды. Внутри волны появляются собственные гармоники. Это прямое предложение пользователя.

В Wave bank нельзя округлять частоты к общей ноте сверх явно установленного `harm`, запускать все волны на `f0`, смешивать готовую пилу с прежним сигналом вместо замены синусоид либо независимо расстраивать гармоники одной волны. Filter, в свою очередь, не должен звучать суммой волн на частотах мод.

Частоты Wave bank: `h*f_j`. Частоты Filter: `k*f0`. Для Sine Wave bank сводится к сумме исходных мод с общим ограничением полосы; ниже `0.40*sr` оно не меняет амплитуды. Для Saw/Square это разные спектральные конструкции, даже при одинаковом названии волны.

**Граница вывода:** гармонический ряд Filter не гарантирует узнаваемую пилу/меандр после фильтрации. Wave bank не обязан перестать быть металлическим: отношения между основными частотами волн остаются лапласиановскими. Обещания классического detuned saw в этой поставке нет. Возможный полезный результат — и новое самостоятельное семейство.

Геометрия и распределение фигур по голосам — те же, что у существующего baseline `laplacian` через `analyse`/`LegacySynthEngine`; спектральная математика — существующие функции ядра без новой приближённой версии Лапласиана. Не вводить в этом сравнении новый трекер фигур или исправление сегментации только на стороне кандидатов. Исходный Jam и все его фазы находятся вне шва; полный 8-связный граф preflight совпадает с графом baseline в этих условиях. На шве сохраняется известное поведение старой сегментации; его исправление — отдельная задача. Для `fullshape=0` использовать существующее значение настройки, а не игнорировать её. `dyn` получает прежнее поле возбуждения, изменяет спектральные веса при соответствующих настройках и не создаёт ударов.

На компактных формах без шва, при одинаковых семи параметрах, исходные `(f_j,a_j)` обеих сторон должны совпадать с текущим Laplace. Старые пределы числа мод относятся к числу лапласиановских источников; **не обрезать волновую таблицу до 20 её гармоник** из-за старого размера массива мод.

## 3. Точный закон волн

`theta` — фаза ОСНОВНОЙ частоты конкретной волны. Для обеих веток используются одинаковые коэффициенты:

```
c_h(Sine)   = 1 при h=1, иначе 0
c_h(Saw)    = 1/h
c_h(Square) = 1/h при нечётном h, иначе 0
W(theta; f) = sum_{h>=1} c_h * b(h*f) * sin(h*theta)
```

Это пила одной фиксированной полярности и меандр с заполнением 50%; DC отсутствует. Амплитуда основного тона равна 1 до частотного ограничения. Отдельной нормировки каждой волны на peak/RMS нет. Разницу общих уровней сцен компенсирует постоянная калибровка, раздел 7.

Единое ограничение полосы для частоты `nu` при частоте дискретизации `sr`:

```
b(nu) = 1,                                         nu <= 0.40*sr
      = 0.5*(1+cos(pi*(nu-0.40*sr)/(0.05*sr))),      0.40*sr < nu < 0.45*sr
      = 0,                                         nu >= 0.45*sr
```

Ограничивать гармоники относительно реальной частоты КАЖДОЙ волны, а не только относительно `f0`. Простые `sign(sin)`/пилообразный modulo без ограничения полосы непригодны. Если используются таблицы с интерполяцией, сверить с прямой конечной суммой: нежелательные зеркальные составляющие интерполяции не считать новым характером метода. Фазы гармоник связаны через `h*theta`; независимые случайные фазы дадут другой сигнал и не являются реализацией этой пробы.

### 3.1 Wave bank

Для одной фигуры в установившемся состоянии:

```
y_W(t) = sum_j a_j * W(theta_j(t); f_j)
theta_j'(t) = 2*pi*f_j
```

Кратные/совпадающие моды учитываются так же, как в исходных массивах; не удалять их молча. Фаза каждого источника хранится. При совпадении частот амплитуды складываются с учётом фаз, а не через сумму мощностей. Переключение волны сохраняет основные фазы.

Sine — режим исходной суммы мод; его стационарное совпадение с `sum_j a_j*b(f_j)*sin(theta_j)` обязательно. У всех исходных мод готовых сцен `b(f_j)=1`. Основной baseline в записях — сам существующий движок `laplacian`, а не произвольная новая реализация синусоидального звука. До сравнения кандидатов технически проверить Wave bank / Sine против этого движка на полном Jam, включая смены поколений и хвосты: при одинаковых фазах, gain и условиях PCM должен совпадать побайтно. Синусоидальный путь можно напрямую использовать из прежнего рендера. Если совпадение нарушено новой обвязкой, исправить обвязку; нельзя принять её за новый baseline только потому, что обе версии используют синусоиды.

### 3.2 Filter

Для фигуры получаем `r_j=f_j/f0`. Индексы `k=1...K`, где `K` — наибольшее целое с `k*f0 < 0.45*sr`. Одна и та же маска используется для Saw и Square:

```
P_k = sum_j a_j * exp(-0.5 * (log2(k/r_j)/sigma)^2)
E_k = P_k / max_{m=1...K} P_m
H_k = 10^(-D*(1-E_k)/20)
A_object = sqrt(sum_j a_j^2)
y_F(t) = A_object * sum_k c_k * b(k*f0) * H_k * sin(k*theta_0(t))
theta_0'(t) = 2*pi*f0
sigma = filter_width_oct; D = filter_depth_db
```

Нормировка `E` берётся по ВСЕМ `k`, в том числе по чётным, которых нет у Square. Поэтому замена волны не перестраивает скрытым образом сам фильтр. Вычислять профиль по исходным выбранным `(f_j,a_j)`, не по гармоникам Wave bank. Частотное растяжение, перенос полос вверх и специальное усиление фундаментала не добавлять.

Если нет ненулевых весов/частот, либо `max P <= 1e-12`, фигура молчит. В частности, одиночная клетка и пустое поле не запускают голую несущую даже при D=0. Для обычных фигур `10^(-D/20) <= H_k <= 1`: фильтр только ослабляет. D=0 даёт исходную волну с `A_object`; это диагностический bypass, не отдельный пользовательский опыт.

`A_object` сохраняет зависимость общего масштаба от весов мод. Это часть определённого закона, не автоматическое выравнивание громкости фигуры. Конечные уровни разных состояний могут различаться. Не добавлять нормировку выхода по мгновенному RMS.

Реализация — спектральная маска с синтезом периодической таблицы. Это соответствует заданной амплитудной характеристике в установившемся состоянии. Произвольный IIR-банк с собственными хвостами, фазовой характеристикой и резонансом не эквивалентен этой пробе и не подменяет её без уточнения ТЗ.

## 4. Временная обвязка и сохранность baseline

Первый опыт использует непрерывный синусоидальный Laplacian как baseline, без перехода в событийные Objects. **Прежние отдельные правила 20 ms и новый трекер, предложенные Researcher в первоначальном ТЗ, отменены:** они добавляли бы изменение артикуляции к исследуемой смене спектрального метода.

Для кандидатов сохранить анализ голосов, аудиочасы, базовые фазы, огибающие и время отпускания существующего baseline. В текущем LegacySynthEngine `GEN_ATTACK_DEFAULT=0`, `GEN_DECAY_DEFAULT=0`, `GEN_SUSTAIN_DEFAULT=1`, `GEN_RELEASE_DEFAULT=0.1` доли поколения; перевод в блоки остаётся штатным. Не заменять их новой атакой/затуханием и не менять baseline ради совпадения.

- Wave bank меняет только периодическую волну звучащей моды. Её частота, вес, фаза, огибающая и уход в хвост берутся из того же пути, что у baseline; гармоники наследуют фазу и огибающую своего источника. Смена частоты остаётся амплитудным переходом со старой на новую, без глайда.
- Filter обновляет целевую спектральную маску по тем же анализам поля и сохраняет тот же масштаб времени сглаживания/отпускания голосов. Внутри сохраняющейся фигуры меняются коэффициенты гармоник одной несущей, её фаза продолжается. Собственного резонансного хвоста, нового событийного возбуждения или дополнительной общей ADSR нет. Различие переходов, которое неизбежно следует из замены нескольких частот одной несущей, описать в техническом отчёте; не приписывать его новому независимому механизму артикуляции.
- Смена Sine/Saw/Square или метода плавная, не сбрасывает поле и сохраняющиеся фазы. Не обрывать незаконченный переход при новом вмешательстве. Повторный анализ неизменного состояния не создаёт нового события сверх поведения baseline.
- Все варианты — центр, одинаковые L/R. Пауза КА замораживает форму и оставляет аудио работать; Stop останавливает весь звук. Сохраняются фазы, ramps и хвосты для точного Replay/Continue.

Техническое совпадение Wave bank / Sine с действующим baseline на полной сцене — обязательная проверка до выдачи набора. Старые движки, записи и эталоны не переписывать. Для Filter равенство звука baseline не требуется: различие спектрального закона и есть предмет пробы.

### 5.1 Карточки решений

**R / F-saw и R / F-square.** Неизвестно, даёт ли смена резонансов формы на окраску гармонической волны полезное расширение относительно нынешнего звука, сохраняя различимые фазы Jam. Предсказание: вместо изменения сочетания лапласиановских тонов меняется окраска ряда `k*f0`. В Square чётных гармоник нет, поэтому некоторые полосы профиля вообще не попадают в выход: это отдельный риск потери рисунка, которого Saw не проверяет. В отличие от прежних опытов здесь новый спектральный закон и конкретный кандидат непосредственно сопоставлен с текущим baseline. При полезном расширении с сохранением формы развивать Filter; при потере рисунка/неинтересном звуке не продолжать эту маску без новой причины. Слушатель оценивает характер и полезность различий; частотная решётка сама по себе этого не устанавливает.

**R / W-saw и R / W-square.** Неизвестно, даёт ли замена волн мод полезное новое семейство, сохраняя узнаваемую реакцию на фазу фигуры. Предсказание: прежние основные частоты/веса сохраняются, но каждая получает собственный полный либо нечётный ряд гармоник. Это может дать новый насыщенный характер или неинтересное сгущение прежней смеси — исход решается на слух. В отличие от демонстрации обычного переключения осциллятора проверяется сумма нескольких волн на меняющихся негармонических частотах КА. При полезном результате развивать сменную волну, при маскировании рисунка не наращивать слои/детюн автоматически. Слуховая оценка определяет, остаётся ли слышимой жизнь формы и полезен ли новый характер.

**F-saw / W-saw и F-square / W-square.** После непосредственной оценки каждого относительно R неизвестно, дают ли методы взаимодополняющие возможности либо один предпочтителен для выбранного применения. Предсказание: у F меняется окраска общей гармонической основы, у W — сочетание волн на разных лапласиановских частотах. При различной полезной роли сохранить оба; при предпочтении одного направить следующую работу на него; если оба неинтересны относительно R, само различие F/W не объявлять успехом. Слушатель нужен для сравнения музыкальной роли и удобства слышать/менять форму. Пользователь явно заказал и этот этап; он не зависит от положительного вердикта первых пар.

### 5.2 Notes — по одному абзацу на запись

**1. `lc_saw_baseline_filter`:**

> Гипотеза - А — исходный Laplacian на синусоидах. В Б тот же Jam окрашивает пилообразную волну через лапласиановский фильтр. Ожидаем изменение характера и другой способ слышать три состояния фигуры. Проверяем, появляется ли полезный звук относительно А и остаются ли изменения фигуры различимыми.

**2. `lc_saw_baseline_bank`:**

> Гипотеза - А — исходный Laplacian на синусоидах. В Б каждая его синусоида заменена пилой при тех же основных частотах и весах. Ожидаем новый характер при сохранении рисунка исходных тонов. Проверяем, расширяет ли это звучание или дополнительные гармоники только перегружают и скрывают жизнь фигуры.

**3. `lc_square_baseline_filter`:**

> Гипотеза - А — исходный Laplacian на синусоидах. В Б фигура управляет фильтром меандровой волны, у которой отсутствуют чётные гармоники. Часть лапласиановского рисунка может поэтому не попасть в звук. Проверяем, даёт ли Б полезный новый характер относительно А и слышны ли по-прежнему три состояния Jam.

**4. `lc_square_baseline_bank`:**

> Гипотеза - А — исходный Laplacian на синусоидах. В Б каждая исходная частота звучит собственным меандром. Ожидаем изменение окраски с сохранением движения основных тонов. Проверяем, получается ли интересный характер для игры и не теряется ли реакция на фигуру в смеси этих голосов.

**5. `lc_saw_filter_bank`:**

> Гипотеза - Теперь сравниваем два варианта пилы, уже сопоставленных с исходными синусоидами: А — лапласиановский фильтр, Б — пила на каждой частоте моды. Ожидаем разное поведение окраски и сочетания тонов на тех же состояниях Jam. Проверяем, дают ли способы разные полезные возможности или один из них предпочтительнее; различие само по себе не означает улучшения относительно baseline.

**6. `lc_square_filter_bank`:**

> Гипотеза - Теперь сравниваем два варианта меандра, уже сопоставленных с исходными синусоидами: А — лапласиановский фильтр, Б — меандр на каждой частоте моды. Проверяем, какой способ лучше сохраняет интересный рисунок фигуры и нужны ли оба. Если оба уступают исходному звуку, их взаимное различие не считаем успехом.

## 6. Что уже проверено до ТЗ

Preflight использовал неизменённые функции `_select_modes` и `laplacian_modes`, извлечённые из AST текущего `casynth_core.py` (`sha256` и базовый commit записаны в JSON), независимый полный 8-связный торовый граф и независимый B3/S23. Исходники синта не менялись. **Проверены спектральные данные; аудио нового движка не рендерилось и не прослушивалось.**

- Исходное поле Jam возвращается точно через 3 поколения. В фазах 0/1/2 звучащие компоненты содержат `[7,3,3]`, `[11,3]`, `[16]` клеток.
- Крупнейшие компоненты дают отношения выбранных частот `[1,1.801938,2.246980]`, `[1,3.626833,5.070636]`, `[1,4.649175,5.982671]`. Это различия не только общего уровня.
- У Filter для них положения максимума среди гармоник — 2, 4, 5. Фактические коэффициенты первых 16 гармоник, включая слабые, сохранены для всех компонент и волн. Проверка относится к каждой фигуре; итог при наложении живых голосов и кроссфейдов Developer обязан проверить в рендере.
- При `110 Hz` гармонический ряд Filter содержит частоты до `19800 Hz`, верх ограничен общим taper. Для Wave bank верх считается отдельно на каждой частоте моды.
- Перенос и поворот проверенных графов сохранили частоты/веса (max absolute difference 0 в этой пробе). Повторные неизменные фазы сохраняют спектры.
- В JSON есть две неподвижные шестиклеточные формы Beehive и Ship с разными спектрами — служебная проверка зависимости от геометрии при равном числе клеток. Это не дополнительное обязательное прослушивание.

Расчёт показывает, что механизм способен менять предусмотренные составляющие. Он не устанавливает, что различие будет слышно/полезно в готовой сцене. Например, совпадающие частоты разных голосов складываются с фазами; сумма квадратов коэффициентов из диагностики не является RMS готовой смеси.

## 7. Допуск к прослушиванию и сдача Developer

Нужны технические проверки именно нового закона и предъявляемого материала:

1. **Общие исходные данные.** На всех фазах Jam исходные `(f_j,a_j)` baseline, Filter и Wave bank совпадают с preflight и существующим Laplace на этих компактных формах. Проверить применение семи параметров в их действующих областях; `dyn` испытывать при shape>0 и ненулевых событиях, а не объявлять неработающим на default.
2. **Волны и спектральная опора.** Sine/Wave bank равен исходной конечной сумме при заданных фазах с учётом общего `b(f_j)`; в готовых сценах все эти множители равны 1. Дополнительно полный рендер Sine/Wave bank на Jam совпадает побайтно с действующим baseline до калибровки. Для Saw/Square проверить веса гармоник и их связанные фазы. У Filter выходные стационарные линии лежат на `k*f0`; у Square чётных нет. У Wave bank линии лежат на `h*f_j`, не на принудительной общей решётке. Проверять и тестовый нецелый `f_j/f0`. Совпадения частот не терять и не суммировать через мощности. Стороны А/Б меняются по таблице сравнений, поэтому проверки назначаются по методу, а не по букве стороны.
3. **Filter.** Формулы и коэффициенты совпадают с независимым прямым расчётом; маска одинакова у Saw/Square. D=0 равен исходной волне с заданным масштабом; пустая/одноклеточная фигура молчит. Глубина и ширина действуют при паузе без переинициализации фазы. Нормировка не зависит от отсутствия чётных гармоник у Square.
4. **Полоса и качество таблиц.** Сверить установившиеся сигналы с прямым полосно ограниченным суммированием на низких/высоких и нецелых частотах. После выравнивания одной начальной фазы относительный RMS ошибки таблицы к референсу <= -60 dB; для прямой суммы — численная точность. Не включать startup/ramp в этот тест. Показать спектр ошибки, проверить `b(nu)` и фактический конец спектра; отдельный тест на 1760 Hz и на высокой лапласиановской моде ловит неверное ограничение по одному `f0`.
5. **Время.** На живом Jam проверить сохранность временного поведения baseline в Sine/Wave bank, плавные смены волн/параметров, обработку смены состава фигур и Resume. Поле на паузе продолжает звучать; Stop молчит. Быстрое рисование не обрывает незавершённый кроссфейд. Отдельно сверить, что Filter не получил новый независимый закон возбуждения/огибающих.
6. **Готовые записи.** Калибровать пять вариантов R, F-saw, W-saw, F-square, W-square один раз на полных 12 s. У каждого — собственный постоянный множитель относительно общего целевого RMS, отклонение не более 0.5 dB от цели; тогда в любой паре разница не более 1 dB. Это не обещание равной субъективной громкости. Один и тот же множитель варианта используется во всех его появлениях независимо от стороны А/Б. Общий headroom выбрать так, чтобы все пять вариантов не клиппировали; указать исходные уровни, коэффициенты, конечный peak и clip count. Проверить хешами: R одинаков во всех четырёх baseline-парах, а каждый кандидат одинаков в baseline-паре и в прямой паре методов, включая итоговую калибровку. Ни AGC, ни нормировка каждого поколения/фигуры, ни сатурация для маскировки перегруза не допускаются. Свободная смена параметров не пересчитывает калибровку автоматически.
7. **Воспроизводимость.** Полные параметры, источники таблиц/версия закона, фазы, ramps, уходящие голоса и состояние распределения по слотам входят в сохранение. Replay всех шести записей точен; Continue точен, в том числе из середины кроссфейда и после переключения волны/способа. Не делать звук зависимым от попадания в кэш или скорости UI. Сначала коммит звукового кода, затем сборка закреплённого каталога с `require_pinnable()`, как у прежних опытов.
8. **Бюджет и сохранность.** Измерить p99 блока и худшие блоки анализа/перестроения таблиц на готовых сценах, вместе с обновлением поля: штатный бюджет блока ~7.98 ms. Превышение не скрывать средним. Не раздувать глобальные старые пулы ради гармоник нового движка; реализацию оптимизации выбирает Developer. Пройти соответствующие новые тесты и полный `check.py`; старые аудиоэталоны неизменны. UI-эталон обновляется только при реальном согласованном изменении UI. Ограничения за пределами готовых сцен перечислить отдельно.

До пользовательского прослушивания Researcher сверяет фактические WAV и реализацию с формулами и эпизодами: есть ли ожидаемая смена спектра после сглаживания и сложения, не исчезла ли она целиком из-за отсутствующих гармоник, не подменена ли клиппингом/алиасингом/провалом уровня. Если материал не содержит предсказанного поведения, вернуть постановку на техническую доработку; не выдавать ненулевой diff за успех и не добавлять ещё набор обязательных контрольных прослушиваний.

## 8. Решения после слухового результата

Сначала зафиксировать по четырём парам с R, что каждый кандидат добавил и потерял относительно синусоидального baseline. Затем по прямым парам F/W определить различия полезных ролей или предпочтение. Победа одного кандидата над другим не заменяет первой оценки: оба могут оказаться хуже baseline.

| Результат | Следующий шаг |
|---|---|
| Wave bank относительно R даёт полезный новый характер и сохраняет реакцию на форму | Сохранить сменную волну как перспективную ветку; отдельно рассмотреть перенос в событийные Objects |
| Filter относительно R даёт полезный характер и различимую эволюцию | Развивать роль КА как спектральной маски; отдельно проверить исполнение нот/артикуляцию |
| Оба полезны и различаются | Сохранить оба способа; пользователь выбирает следующий сценарий применения |
| Новый характер есть, но жизнь/правки поля почти не слышны | Эта конкретная схема не прошла требование связи с КА; не считать расширение палитры само по себе полным успехом |
| Оба остаются неинтересными/слишком похожими на прежнее | Сохранить результаты и исходный Laplacian, убрать эти законы из ближайшей полировки; вернуться к другому принципу чтения формы |

Отрицательный результат конкретной маски с выбранной шириной/глубиной не доказывает невозможность любых фильтров. Возвращение к настройке требует причины и предсказания нового поведения; просто перебор значений не становится следующей слуховой задачей.
