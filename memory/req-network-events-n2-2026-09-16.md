# N2 — события поля возбуждают сеть задержек

2026-09-16. **ТЗ для Developer, реализация ещё не выполнена.** Пользователь поручил подготовить следующий опыт: событийное возбуждение сети в сравнении с перестройкой частот. Формулы и настройки ниже — экспериментальная постановка Researcher; пригодность звука ещё не установлена.

## Вопрос и основание

В [фидбеке N1](research/network-n1-hypotheses-2026-09-16.md) периодическая «сирена» от перестройки частот доминирует над дополнительными фактурами. Проверяем гипотезу: если изменения клеток подают возбуждение в сеть, периодичность, положение и плотность событий будут слышны через атаки, резонансы и их затухание. Это даст ответ, стоит ли дальше исследовать событийную сонификацию.

**Сравнение двух способов:** А — поле перестраивает частоты Gutter; Б — события поля возбуждают отдельную сеть задержек с затухающей обратной связью. Обе стороны получают одно живое поле. Это сравнение моделей целиком: из его результата нельзя отдельно вывести эффект только возбуждения или только топологии.

**Смена модели Б сделана явно.** В численной пробе импульс вместо внутреннего источника Gutter запускал длительное самовозбуждение. Кроме того, связи Gutter меняют демпфирование принимающего узла, а не непосредственно подают в него сигнал. Для проверки отдельных откликов и передачи сигнала используем описанную ниже новую модель. Она не является портом Gutter. N2 — номер опыта, а не версия исходной сети.

## Общий способ чтения положения

Чтобы жёсткие границы восьми областей N1 не определяли результат сравнения, обе стороны используют одинаковые перекрывающиеся периодические веса. Для поля H×W, клетки (r,c), узла i=4·l+j, j=0…3, l=0…1:

```text
x = (c + 0.5) / W;              y = (r + 0.5) / H
ax = (j + 0.5) / 4;             ay = (l + 0.5) / 2
dx = ((x - ax + 0.5) mod 1) - 0.5
dy = ((y - ay + 0.5) mod 1) - 0.5
h(d,s) = (1 + cos(pi*d/s))/2     при |d| <= s; иначе 0
K_i(r,c) = h(dx,1/4) * h(dy,1/2)
```

`K_i >= 0`, сумма восьми весов в каждой клетке равна 1. Веса непрерывны на торе; перенос фигуры меняет распределение по узлам, поскольку их задержки / частотные банки различаются. Дискретные шаги КА сохраняются. Отсутствие слышимых всплесков на границе остаётся проверяемым результатом.

## А — частотный способ

Основа — `casynth_lab/gutter_field.py` и фиксированная конфигурация `gutter_field_n1_config.py`. В новом движке заменить только подсчёт клеток областей на `n_i = sum(K_i * G)`, добавить фиксированный выходной trim из раздела уровней. Остальная математика Gutter, внутренний источник, маршруты и состояния сохраняются.

```text
u_i = n_i / (n_i + 2)
ratio_i = 2^clip(log2(scale) + depth*(2*u_i - 1), -1, 1)
f_ij = float32(min(19000, base_ij * ratio_i))
```

Во всех трёх записях: `scale=1`, `depth=1`, `interaction=127`, `freeze_ca=0`. Поле меняет частоты на границе блока; состояния узлов и задержек при этом продолжаются. В готовых сравнениях нет дополнительных каналов N1 «поле → демпфирование / связи».

## Б — событийная сеть

Все числа этого раздела задают одну конфигурацию N2 при SR=44100, блоке 352 отсчёта. Расчёт float64; отдельные `model_version` и `STATE_VERSION`. Реализация при другом SR не входит в опыт: неподдерживаемый контекст отклонять явно.

### События и импульс

На границе очередного аудиоблока `G_prev` — поле, уже обработанное предыдущим render, `G` — итоговое текущее поле после команд и шагов КА:

```text
E = (G != G_prev)
e_i = sum(K_i * E)
a_i = e_i / (e_i + 2)
G_prev = copy(G)
```

Рождение и смерть клетки дают положительное событие; они не взаимоуничтожаются как знаковые суммы. Несколько обновлений внутри одного блока сводятся к итоговому изменению поля: промежуточные переходы, вернувшиеся к исходному состоянию, не озвучиваются отдельно. В выбранных сценах между блоками не бывает нескольких поколений. Повторная передача того же поля не создаёт возбуждения. Существующий аргумент `exc` содержит удерживаемое состояние другого алгоритма: его нельзя повторно добавлять в каждом блоке как новые события.

На свежем init/reset буферы и состояния нулевые, `G_prev=0`: исходные живые клетки дают один начальный пакет. `update_field` сохраняет последнюю копию поля до render. При restore восстановить сохранённые поля и состояния без повторного начального пакета. Пауза КА оставляет затухающий отклик; рисование продолжает создавать события. Изменение параметров само по себе событием не является.

На пакет добавить `a_i` в оба состояния `z_fast[i]`, `z_slow[i]`. Затем для каждого отсчёта сначала вычислить возбуждение, после — затухание состояний:

```text
q_fast = exp(-1 / (SR*0.00025))
q_slow = exp(-1 / (SR*0.002))
exc_i = 0.75 * ((1-q_fast)*z_fast[i] - (1-q_slow)*z_slow[i]) / (q_slow-q_fast)
z_fast[i] *= q_fast
z_slow[i] *= q_slow
```

Изолированный пакет начинается с `0.75*a_i`; сумма его знаковых отсчётов до нелинейности равна нулю на бесконечном хвосте. Перекрывающиеся пакеты складываются в состояниях. События непосредственно подают сигнал в сеть.

### Задержки, связи, потери

Восемь линий задержки, длины в отсчётах: `D=[149,211,293,401,547,743,1009,1361]`. Матрица обратной связи `M_ij=0.25-delta_ij`: диагональ −0.75, остальные элементы 0.25; `MᵀM=I`. Фильтр потерь: `q=exp(-2*pi*6000/SR)`.

Для каждого отсчёта k сначала прочитать **все** задержки и обновить **все** фильтры, затем рассчитать и записать новые значения:

```text
d_i[k] = v_i[k-D_i]                          # история до k=0 нулевая
l_i[k] = (1-q)*d_i[k] + q*l_i[k-1]
v_i[k] = tanh(exc_i[k] + rho*sum_j(M_ij*l_j[k]))
```

Таким образом, сигнал одного узла действительно попадает в другие через задержанную обратную связь. `rho=0.88` во всех записях. Одна ручка Б: «Отклик», `rho=0.60…0.95`, при ручном изменении линейная рампа 20 мс; рампа входит в snapshot. Длины, матрица, сила и форма импульса фиксированы для этого опыта.

Выход снимается с `l_i`. Для i=4·l+j, `p_i=(j+0.5)/4`:

```text
L = sum_i(cos(pi*p_i/2)*l_i) / 8
R = sum_i(sin(pi*p_i/2)*l_i) / 8
```

Выходного обходного пути от импульса нет. Источник энергии Б — события поля. При нулевом состоянии и отсутствии событий выход нулевой; после прекращения событий сеть затухает. Ортогональная матрица, фильтр потерь, `rho<1` и `|tanh(x)|<=|x|` задают затухающую обратную связь. При нормальных событиях это не повод сбрасывать или переинициализировать сеть.

## Уровни сравнения

Единая калибровка для всех трёх записей: выход А, уже содержащий существующий множитель 20, дополнительно умножить на `10^(-16.5/20)`; выход Б из формул L/R умножить на **96**. Затем один раз применить общий `gain` стенда; его изменения рампировать по существующему контракту. Начальные `vol=0.7`, `level=1`, `gain=0.028`. Сохранять состояние выходной рампы.

Коэффициенты фиксированы между сценами и во время игры. Автоматическая подстройка по текущему полю изменила бы проверяемую динамику. В предварительном расчёте RMS после калибровки: А −37.1/−36.9/−36.4 dBFS, Б −35.4/−39.7/−35.2 dBFS (порядок: ритм / движение / рост, моносумма, секунды 2–12). Разница до 2.9 dB не является доказательством равной воспринимаемой громкости; в выводах различать характер и уровень.

Предварительные стереопики Б в сценах — 0.132/0.129/0.159. В дополнительной пробе переключения всего поля каждый блок при `rho=0.95`, `gain=0.04` пик 0.972. Это ограниченная проверка запаса, а не гарантия для произвольного сигнала. Перед поставкой измерить реализацию и обычные ручные правки; клиппинг не должен объяснять ожидаемую фактуру. При расхождении вернуться к калибровке с Researcher, сохраняя один набор коэффициентов для всех опытов.

## Три опыта и готовые Notes

Общее: Conway B3/S23, тор 32×32, обе стороны с указанными настройками, эволюция включена, запись 12 с от свежего старта. Координаты нулевые, (строка, столбец); точные клетки также в [данных предварительной проверки](research/network-n2-preflight-2026-09-16.json). Все фигуры продолжают эволюцию после конца записи. Названия сторон: «А — поле меняет частоты», «Б — события возбуждают сеть».

**N2.1 — Ритм.** Pulsar, 6 поколений/с. Клетки: объединение произведений `{0,5,7,12} × {2,3,4,8,9,10}` и `{2,3,4,8,9,10} × {0,5,7,12}`, затем обе координаты +9. Период 3 поколения, цикл 0.5 с; 32–56 событий на шаг.

> Гипотеза - Периодическая фигура в А будет повторять изменения высоты и окраски, а в Б — давать повторяющийся рисунок атак со звенящими затуханиями между ними. Проверяем, слышен ли этот рисунок как самостоятельное поведение, а не только очередное ровное жужжание.

**N2.2 — Движение.** Glider, 16 поколений/с. Клетки: `(0,1),(1,2),(2,0),(2,1),(2,2)`, обе координаты +28. Пять живых клеток и четыре события на каждый шаг; полный обход тора за 128 поколений, 8 с. Это отделяет влияние положения от общего числа событий. В первых секундах фигура пересекает внешний край.

> Гипотеза - При движении фигуры в Б должны меняться окраска и расположение звенящих откликов, хотя число событий остаётся одинаковым. В А ожидается движение высоты и окраски. Проверяем, даёт ли положение события слышимый характер и не выделяется ли край поля отдельным всплеском.

**N2.3 — Рост.** R-pentomino, 6 поколений/с. Клетки: `(0,1),(0,2),(1,0),(1,1),(2,1)`, обе координаты +14. За запись проходит нерегулярную эволюцию; на поколении 72 остаётся 71 живая клетка, следующий шаг даёт 66 событий.

> Гипотеза - При нерегулярном росте в Б отдельные атаки будут переходить в перекрывающуюся дробную, шероховатую фактуру, а в А — в изменения высоты и плотности непрерывного звука. Проверяем, даёт ли событийный способ разные типы поведения при редких и плотных изменениях, а не только прибавляет громкость.

## Проверки до передачи пользователю

Developer приносит готовый каталог и короткий отчёт; Researcher сверяет реализацию с этим ТЗ до прослушивания пользователем.

1. **Математика и причинность.** Независимый скалярный расчёт Б совпадает с ускоренным ядром на одиночном и перекрывающихся пакетах. Проверить сумму K, периодичность краёв, XOR рождения/смерти, отсутствие повторов на неизменном поле, объединение правок блока и однократное возбуждение при init. Один импульс в узле i впервые появляется на его выходе через D_i, в другом узле j через D_i+D_j; это проверить по состояниям, а не только по общей громкости. Нулевое состояние без событий остаётся нулевым, хвост затухает без reset.
2. **Живые сцены.** Проверить период pulsar=3, glider=128 и четыре события/шаг; продолжающуюся эволюцию всех сцен из конечного snapshot. На обеих сторонах правка поля из одного и того же сохранённого состояния даёт реакцию относительно продолжения без правки. Для Б отдельно показать эффект переноса одинакового события между узлами: изменение временного / спектрального рисунка после выравнивания энергии; численный неноль ещё не доказывает слышимость.
3. **Уровень и исполнение.** Отчёт по RMS/пикам/clip/resets каждой стороны и сцены, плотным/случайным полям, повторным ручным правкам и концам ручки «Отклик» при максимальном штатном gain. Сохранить полевые траектории диагностик. Без NaN, клиппинга и аварийных reset в этих проверках; суммарное время обеих сторон после прогрева p99 меньше блока 352/SR≈7.98 мс на машине стенда.
4. **Контракт стенда.** Snapshot включает буферы задержек и их позиции, фильтры, импульсы, предыдущий/ожидающий грид, параметры, рампы и версии. Replay A/B/monitor и Continue совпадают байт-в-байт, restore не добавляет импульс. Старые записи и Notes остаются воспроизводимы. Пройти `python check.py` и новые проверки N2.

Визуализация Б в стенде должна помогать связать действие и отклик: позиции восьми узлов и текущая сила событий / уровень отклика. Жёсткие прямоугольники N1 не обозначают области действия новых весов. Счётчики, матрицы и внутренние версии оставить в техническом отчёте.
