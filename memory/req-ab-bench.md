## Спецификация

**Окно (pygame), три зоны:**
1. **Тулбар сверху:** ряд кнопок тест-кейсов. Выбор кейса → ОБА поля сбрасываются на initial-состояние кейса, симуляция стоит, тишина.
2. **Два поля A и B рядом** (одинаковая геометрия, одинаковый initial из кейса). Клик по полю → это поле сбрасывается на initial кейса, начинает бежать и ЗВУЧАТЬ; другое поле останавливается и молчит (замирает как есть). Повторный клик по тому же полю = рестарт с initial. В каждый момент звучит максимум одно поле. Выбранное поле подсвечено рамкой. Рисования клеток мышью НЕТ (кейсы фиксированные) — клик только рестарт/выбор.
3. **Панель ручек сбоку:** редактирует параметры ВЫБРАННОГО поля, с явной подписью «A»/«B». Per-field параметры (у каждого поля свои, хранятся раздельно): селектор движка из реестра `ENGINES` + динамическая панель параметров движка по param-спекам реестра (для Laplacian: part/spread/alpha/shape/harm/dyn/full) + ENV-блок (Attack/Decay/Sustain/Release, tune) — как в gol_synth. Общие (не per-field): note (несущая, слайдер по MIDI-номеру, дефолт как в синте), vol, speed (тиков/сек). Дефолты полей = дефолты реестра.

**Тест-кейсы (захардкоженные данные: имя + размер поля + список (паттерн, x, y) из `patterns.py`):**
1. `block` — одиночный блок-натюрморт (контроль: событий нет).
2. `beacon` — осциллятор beacon (стабильные углы + мигающий центр).
3. `r-pentomino` — хаос в центре большого поля.
4. `glider` — глайдер на большом поле, курсом в пустоту (не касается кромки минимум ~30 тиков).
5. `glider-vs-block` — глайдер курсом на блок, столкновение через ~8–15 тиков.
Размеры полей подобрать (глайдерным кейсам — просторно; сегментация не wrap-aware, шва тора избегать).
