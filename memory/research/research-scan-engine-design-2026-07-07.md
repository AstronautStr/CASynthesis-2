# Дизайн: движок `scan` — «волны по пластине» (дверь E+)

_2026-07-07, Researcher. Статус: **ПРЕДЛОЖЕНИЕ** (в decisions.md не внесено — ждёт
акцепта Пользователя). Источник идеи: демка E (scanned-синтез) + фантазия Пользователя
«пластина спокойно живёт; глайдер врезается — звук растекается кругами по воде».
Канон приёма: Verplank/Mathews/Shaw «Scanned Synthesis», ICMC 2000 (медленная
динамическая система + исполнитель + скан на аудио-частоте; здесь исполнитель = КА)._

---

## 1. Звуковая идея

Существо — упругая поверхность. На ней живёт МЕДЛЕННОЕ поле u (рябь герцовых частот,
видимая глазом). Звук = форма этого поля, считанная вдоль пути обхода живых клеток
f0 раз в секунду. Пока поле спокойно — устойчивый «тон покоя», характерный для формы;
событие автомата (рождения/раны от смертей) впрыскивает горб → круги расходятся →
тембр расцветает и успокаивается. В отличие от Лапласа (форма → статичный спектр)
здесь форма → эволюционирующая волна: спектральный поток, главная нетронутая ось тембра.

## 2. Ключевой факт, определяющий архитектуру

`gol_synth.py:1036`: `analyse()` уже вызывается **каждый кадр** (~60 fps), amps каждого
голоса SlotPool и так глайдит по чанкам. Значит движку НЕ нужна волновая таблица и
отдельный аудио-путь: scanned-синтез пере-выражается спектрально —

- **freqs = k·f0, k=1..n** (гармоники периода таблицы; питч-якорь тривиален, частоты
  константны → у SlotPool нет кросс-фейда хвостов, как у гармонических движков);
- **amps = |rFFT( скан поля вдоль пути )|**, пересчитываются каждый кадр.

Отбрасывается фаза гармоник. Гипотеза (пометка: слуховая, проверить A/B с демкой E):
монауральный слух к статичной фазе почти глух, характер «меандров/треугольников»
задаётся амплитудным спектром (нечётные 1/n, 1/n²) и сохранится.

## 3. Компоненты (все — малые и локальные)

1. **`casynth_core.map_scan(patch, f0, n, stiff=…, damp=…, inj=…, field=None)`** —
   stateless, контракт реестра соблюдён: змейка-путь по живым клеткам `patch`,
   значения `field` вдоль пути → rFFT → амплитуды гармоник 1..n, нормировка.
   `field=None` (или энергия ≈0) → скан самой бинарной формы = детерминированный
   «тон покоя» (нужно и для тестов). `stiff/damp/inj` функцией игнорируются —
   их потребляет интегратор поля (прецедент сквозных kwargs: `fullshape`);
   в реестре они нужны, чтобы динамическая панель ручек построилась сама.
2. **`casynth_engine.plate_step(u, v, grid, stiff, damp, substeps=4)`** — интегратор
   медленного поля на ПОЛНОЙ сетке: leapfrog `v=(v−k·L·u)·(1−d); u+=v`, лапласиан
   8-соседей с wrap, мёртвые клетки зажаты в 0 (граница). Guards: NaN→сброс,
   |u|>bound→rescale. Чистый numpy, тестируется отдельно.
3. **Впрыск событий** — переиспользуем готовый `events_field(prev,new)`:
   на каждом step() `v += inj·exc`. Тот же сигнал, что кормит dyn/acc — ветка
   ДИНАМИКА получает третий выход без нового детектора.
4. **`analyse()`**: движкам, объявившим `field`-параметр, передавать пер-объектный
   срез `field[bbox]·sub` — зеркало готового пути `exc` (маскирование по sub уже
   решает утечку перекрывающихся bbox).
5. **Прототипы**: `gol_synth.py` держит `u,v` рядом с `exc_field`, зовёт `plate_step`
   раз в кадр (фиксированные substeps — НЕ dt-скейлинг, ради детерминизма replay);
   `ab_bench.py` — то же пер-поле → кейс A=Laplace / B=Scan на готовой сцене
   `glider-vs-block` получается почти бесплатно.

Состояние живёт в клетках сетки, не в объектах → трекинг идентичности объектов
(known issue) НЕ нужен: морф/распад/слияние существ поле переживает само, как в демке S1.

## 4. Ручки движка `scan` (v1)

| arg | label | диапазон | дефолт | смысл |
|---|---|---|---|---|
| n | part | 1..20 | 16 | число гармоник (потолок MAX_MODES_PER_OBJ) |
| stiff | stiff | 0..1 | 0.5 | скорость волны (k≤0.24·substeps по устойчивости) → темп растекания |
| damp | damp | 0..1 | 0.4 | затухание ряби (сек звона после события) |
| inj | inj | 0..1 | 0.7 | сила впрыска событий поколения |

v2-кандидат (не в первую итерацию): `diff` — blend волна↔диффузия (диффузия скругляет
скан → темнее «тон покоя», медленное расплывание вместо кругов).

## 5. Критерии приёмки (draft для REQ Developer)

- **A (бит-в-бит):** движок `scan` не выбран → golden-master и 59/59 тестов без изменений.
- **B (покой):** статичная форма, событий нет → amps сходятся к «тону покоя» формы,
  без NaN/DC, стабильны от кадра к кадру.
- **C (поток):** step с рождениями (r-pentomino) → L1-разница amps до/после события
  выше порога; пустое событие (нет рождений/смертей) → разница 0.
- **D (успокоение):** после одиночного впрыска amps возвращаются к «тону покоя»
  за время порядка damp.
- **E (устойчивость):** stiff=1, 100 шагов r-pentomino — конечные значения поля,
  amps в [0,1].
- **F (изоляция):** два объекта с непересекающимися событиями — событие одного
  не меняет amps другого.
- **G (якорь):** freqs всегда = k·f0; транспоз несущей на рендере работает без
  ретриггера хвостов (частоты слотов от кадра к кадру неизменны).
- **H (стенд):** `ab_bench.py --selftest` — кейс glider-vs-block с B=scan даёт
  ненулевую аудио-разницу при событии.
- **Replay:** фиксированные substeps → поле детерминировано по номеру кадра;
  `replay_controls` подхватывает stiff/damp/inj автоматически (авто-захват
  engine_params уже реализован).

## 6. Открытые вопросы (калибровка, решает Пользователь после прослушивания)

1. **Нормировка громкости.** v1: amps нормируются per-frame (max=1) — громкость
   постоянна, событие слышно только тембром. Альтернатива: пустить энергию поля
   в громкость (расцветание и по уровню) — но это территория `acc`, возможно
   правильнее комбинировать scan+acc, а не дублировать.
2. **Фаза отброшена** — если на слух не хватит «жёсткости» демки E, план Б:
   честная волновая таблица в отдельном прототипе (параллельный аудио-путь,
   без SlotPool/ADSR/tune/replay — потому и не выбран первым).
3. **part=20 — потолок**: демка E играла полный спектр скана; 20 гармоник мягче.
   Если «зубов» мало — поднять MAX_MODES_PER_OBJ (отдельный рычаг, трогает ёмкость слотов).
