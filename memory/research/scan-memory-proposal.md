# Scan Memory — отложенное исследовательское предложение

2026-09-09. **ОТЛОЖЕНО, НЕ ЗАДАНИЕ РАЗРАБОТЧИКУ.** Прежнее ошибочное ТЗ сохранено ниже как материал исследования. Пользователь исключил этот движок из разработки стенда; формулировки про S3 и поставку ниже недействительны. Актуальный [S3 — интерфейс движка](../req-demo-lab-s3.md). Реализация и прослушивание этого предложения не проводились.

## Для пользователя — 30 секунд

**Пробуем:** события КА оставляют затухающий след, который участвует в звуке. A — без памяти, B — с памятью. Готовая сцена позволяет стереть отмеченный участок и услышать его остаточный вклад в B.

**Твоя проверка:** сравнить A/B → стереть метку на паузе КА → попробовать другую длительность памяти. [Три конкретных шага](scan-memory-listening-proposal.md). Если механизм работает, но звук неинтересен, это нормальный результат исследования.

## Поставка и границы

- Шестой движок стенда `scan_memory`, подпись **Scan Memory**, собственная звуковая память и непосредственный аудиовыход. Пять прежних движков сохраняются.
- Один готовый JSON v2 `demos/scan_memory_ab.json`; прежний launcher открывает его. Старые демо продолжают открываться явным `--demo`.
- Две ручки: `memory` — 0..1, default 1; `decay_s` — 0.2..4 с, default 2. Тип обеих float. Форма считывания и пространственное сглаживание фиксированы для этой пробы.
- Существующие Start/Stop, Pause CA, Restart, горячие клавиши, копирование настроек сторон и Factory A+B сохраняются. A/B меняет только прослушиваемую/редактируемую сторону.
- Каталог, checkpoint, новые правила КА, набор разных моделей поверхности и оптимизация звукового разнообразия не входят в S3.

Это узкая проба направления S из предыдущего исследования. Она проверяет полезность памяти и подключение нового типа движка, а не обещает богатую палитру. Метод читает поле в абсолютных координатах: перенос фигуры относительно пути может менять звук. Модель не является физической волновой пластиной.

## Метод для реализации

Точные формулы, порядок обновлений и численно проверенный пример находятся в [коротком описании модели](scan-memory-model-proposal.md). Оно является частью задания, а не факультативным исследованием.

Поле пространственно сглаживается. При каждом реальном изменении поля в память **однократно** добавляется сглаженная знаковая разность нового и старого поля. Память затухает по звуковым часам, включая паузу КА. По фиксированному кругу считывается периодическая волна; сохраняются её фазы и гармоники в допустимой полосе. Между состояниями действует причинное сглаживание 20 мс.

**Не использовать** `events_field` старого dyn как источник этой памяти: там другой смысл и знак событий. Повторный анализ, выбор A/B, изменение ручки, копирование настроек или перерисовка окна не создают события поля. При `memory=0` внутреннюю память всё равно обновлять; ручка меняет только её вклад в звук.

Stop/Restart очищают память и фазу. Включение нового движка на уже живом поле инициализирует его из текущего поля с нулевой памятью; предыдущую историю не восстанавливает. Изменение memory/decay_s не обнуляет память и не пересчитывает её прошлое. Копирование настроек не копирует внутреннее состояние; равенство настроек не обещает мгновенного равенства звука после разных историй.

## Подключение к принятому S2

- В `casynth_lab` выделить минимальную границу между общими часами/полем и звуковым состоянием стороны. Требуемые операции: инициализация на текущем поле, получение изменений поля и параметров, следующий аудиоблок, сброс, диагностика. Конкретные классы выбирает разработчик.
- Пять существующих методов работают через адаптер нынешнего SideState/SlotPool с сохранением PCM. Новый движок не проходит через объектную сегментацию, map→freqs/amps и SlotPool.
- Лабораторный реестр объединяет метаданные пяти прежних методов и factory нового. UI, валидация сцен и команд используют этот общий реестр. `casynth_core.ENGINES` и основной синт не обязаны знать новый движок; не добавлять туда фиктивную map-функцию ради совместимости.
- Обе стороны продолжают вычисляться один раз за блок. Новый движок работает с прежним CLI `--side A|B|monitor` и журналом команд. Бэкенд хранит независимую память для каждой стороны, не использует wall-clock или глобальную случайность.
- Показать тонкую линию пути считывания и рамку вокруг четырёх клеток для стирания. Для линии использовать необязательные данные визуальной подсказки движка; для рамки достаточно необязательного `highlight_cells` в сцене v2. UI не содержит второй реализации сонификации или ветки по имени конкретного демофайла.

## Готовая сцена

Поле 32×32, B3/S23, тор, 4 поколения/с, f0=110 Гц, audio.level=1. Живые клетки:

`[(15,7),(15,8),(16,7),(16,8), (15,22),(15,23),(15,24)]`.

Слева блок 2×2 на пути считывания; справа блинкер. Первые четыре клетки входят в `highlight_cells`. Обе стороны `scan_memory`: A `{memory:0, decay_s:2}`, B `{memory:1, decay_s:2}`. Начальный выбор B; запуск из тишины как в S2. Короткая подсказка: «Пауза КА → сотрите отмеченный блок слева → сравните его затухающий вклад в B с A».

## Автоматическая приёмка

1. **Модель:** проверить знаки рождения/смерти, однократность события и точное экспоненциальное затухание U без новых событий. На неподвижном поле с U=0 A/B равны; memory=0 исключает влияние decay_s на звук. Изменение параметра при неизменном поле не добавляет событие.
2. **Рендер:** постоянная по всему полю поверхность после удаления DC молчит; путь проходит через заданные клетки; частоты выше установленного предела удалены из таблицы. Фаза непрерывна; после Pause CA память продолжает затухать, после Stop сброшена. Сравнить реализацию с независимым расчётом формул из описания модели, включая переходы, а не только общий уровень сигнала.
3. **Причинное сравнение:** одинаковая история, пауза КА и удаление отмеченного блока на обеих сторонах дают ненулевую разницу A/B, которая затухает. При A=B она отсутствует. Отдельно показать, что рисунок на самом пути меняет звук; не считать численный эффект доказательством художественной полезности.
4. **Интеграция:** live/offline совпадают для A, B и monitor на сценарии с событием, ручками и A/B; повтор/reset детерминирован. Изменение B не меняет raw A; переключения между native и прежними движками, Copy/Factory и JSON v1/v2 работают. Headless UI проверяет шестой движок, его ручки, линию и метку.
5. **Регрессии и работа:** `python check.py` включает новые проверки и проходит; PCM старых демо и эталоны основного синта сохраняются. Новая штатная сцена — без клиппинга; аппаратный smoke по процедуре S2, с явным статусом, если устройство недоступно. Перегрузки, underrun и недостаточная громкость не выдаются за отсутствие эффекта метода.

Разработчик до сдачи готовит WAV/отчёт проверок в `artifacts/` и один готовый запуск. Пользователю — только три шага из отдельного файла и отчёт до десяти строк. После S3 остановиться.
