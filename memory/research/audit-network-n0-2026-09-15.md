# N0: техническое ревью и выбор опыта N1

2026-09-15. Ревью Researcher по запросу пользователя. Выбор канала N1 ниже — исследовательское предложение для реализации демки, не принятый пользователем способ сонификации.

## Вердикт

В N0 действительно есть восемь динамических узлов, замкнутые связи и задержки. Исполняемый Java-узел воспроизведён; направление и время прихода связи в Python проверены отдельно. Полное соответствие исходному Max-патчу **не подтверждено**: найден лишний маршрут шестого узла, обвязка содержит явно выбранные приближения. Рендеры — материал этого ревью, пользовательской приёмки по WAV нет.

Для следующего живого опыта выбран канал **поле → частоты банков резонаторов восьми узлов**. Широкое управление демпфированием отложено: повторные вмешательства показали длительное преобладание низких частот после первого переключения. Это вывод о пригодности конкретной постановки следующего опыта, не слуховая оценка звука. Точное задание — [N1](../req-network-ca-n1-2026-09-15.md).

## Что проверено заново

- Хеши десяти файлов исходного Gutter совпали с commit `efa4737af31febf09bd746a45bd9cd57c88f74b1`. Хеши всех пяти PCM-файлов и пяти float-файлов N0 совпали с манифестом; float-данные конечны.
- Повторно запущен **оригинальный `gutterOsc.class` на JVM**, 13 сценариев, 6000 отсчётов каждый, трассы состояний на первых 3000. Основной режим atan совпал точно. Режим 5 отличается до 1 ulp на выходе; он в N0/N1 не используется. Совпадение некоторых аварийных результатов с Java — проверка переноса, не утверждение пригодности этих режимов для звука. Число «14 случаев» в отчёте Developer неточно: именованных сценариев 13, дополнительно проверяются размеры блоков.
- 9 тестов N0 прошли. Тест `test_links_reach_damping` сам по себе доказывает только ненулевой буфер, поэтому добавлена независимая исследовательская проверка: единственное ребро 1 → 4, коэффициент 0.75, возбуждён только узел 1. Для задержек 3, 64, 2064 первый изменённый вход приёмника приходит ровно на соответствующем отсчёте. Значения записанной суммы и прочитанного входа совпадают с независимым расчётом, максимальная ошибка 0.
- Контрольный 12-секундный прогон без изменений заново совпал с `raw/02_control_reference.f32.wav` побайтово. Первые 4 секунды `02_control` и контроля совпадают.
- Общий `check.py`: **ALL GATES PASS**, 151 тест; эталонный звук совпал побайтово, кадр интерфейса — попиксельно.

Модель проверенного маршрута: `m_j[k] = Σ_i G[i,j]·0.5·(L_i[k]+R_i[k])`; `c_j[k] = float32(clip(damp_j[k] + interaction[k]·m_j[k−2064], 0.0001, 1))`. Это вход демпфирования узла; сами узлы сохраняют состояния между отсчётами. Проверяется именно такой механизм, а не прежняя четырёхсинусная PM-демка.

## Найденные расхождения и границы проверки

**R1, исправить перед N1: лишний правый выход узла 6.** В [исходном патче](https://github.com/tommmmudd/guttersynthesis/blob/efa4737af31febf09bd746a45bd9cd57c88f74b1/Gutter%20Synth.maxpat), `p individual_controls`, `obj-17` (bpatcher `[6]`) соединён только левым выходом с `obj-93` (`send~ 6L`). У `obj-92` (`send~ 6R`) входных соединений нет. В Python `GutterNetwork.step()` вычисляет и использует оба выхода всех восьми узлов. Добавленное соединение меняет и правый мастер-канал, и обратную связь из узла 6. Исправление: явная маска выходных маршрутов, `R[5]=0` до суммирования и матрицы; левую панораму узла сохранить. В исследовательских пробах это исправление применялось только к экземпляру модели, исходный код не редактировался. Хеши старой поставки относятся к прежней маршрутизации.

**R2, уточнить генератор частот и его описание.** В конфигурации есть 5485.799, 5514.621 и 5437.667 Гц при заявленном диапазоне 50–5000. Тест диапазона использует другой seed и этого не ловит. В источнике сумма двух случайных величин проходит через `multislider obj-29` с `setminmax [0,1]`, затем возводится в квадрат и масштабируется. Python пропускает объект multislider. [Документация](https://docs.cycling74.com/reference/multislider/) задаёт диапазон, но по прочитанному описанию нельзя уверенно установить обработку входного списка за границами. Не объявлять клиппирование доказанным без проверки Max. Для N1 берём **явный список частот из конфигурации**, не обещание воспроизвести случайную загрузку патча; генератор не вызывается заново.

**Четыре допущения Max.** Для N1 зафиксированы условия самостоятельной реконструкции: задержка 2000+64, SVF с коэффициентом `q=0.99`, сохранённые значения узлов из N0, явный банк частот. Это не восстановленное состояние запущенного Max. `delay~` действительно задаёт время в отсчётах, а обычная обратная связь требует разрыва вычислительного цикла; число дополнительных векторов в этом патче без исполнения не установлено. Документация [delay~](https://docs.cycling74.com/reference/delay~/) и [материал Cycling ’74 о feedback](https://rnbo.cycling74.com/learn/delays-in-rnbo). Для [svf~](https://docs.cycling74.com/reference/svf~/) подтверждены семейство Chamberlin и значение resonance по умолчанию 0.01, но не формула `q=1−res`. Точность этой формулы не утверждается.

При проверке чувствительности варианта N1: дополнительные задержки 0/64/128 изменяют спектр; их нельзя считать безразличными. В частотной пробе замена SVF `q=0.99` на 1.98 сохранила близкий измеренный спектр, но это не доказательство точности Max. Перенос этих коэффициентов в N1 явный, версионируемый; требование точной реконструкции Max остаётся отдельным от проверки сонификации выбранной модели.

**R3, ограничить вывод о гистерезисе.** В исходном `02_control` окно 8–12 с после возврата параметра имеет центроид 65 Гц против 898 Гц у контроля; доля энергии 20–100 Гц — 94.7% против 4.7%. Это подтверждает зависимость наблюдаемого результата от истории. Четыре секунды не доказывают разные аттракторы или устойчивый гистерезисный цикл. После исправления R1 повтор 138 → 40 → 138 в течение 28 с также не вернул исходный спектр: на поздних участках 97–99% энергии оказалось ниже 100 Гц. Перезапуском между жестами это не маскировалось.

## Почему следующий канал — частоты резонаторов

Проверен штатный приём исходного патча: масштабирование частот банка с сохранением его состояний. Все новые пробы используют исправление R1, прочие условия N0 фиксированы. Субъективного прослушивания агентом не было.

| Проба | Измеренный результат |
|---|---|
| Общий множитель частот 1 → 0.5 → 1 → 2 | Центроид на последних двух секундах участков: 983 → 302 → 842 → 1996 Гц; уровень соответственно −14.0 / −13.4 / −13.9 / −13.8 dBFS. |
| Те же 12 клеток, другое расположение | При закреплённых полях средний центроид 2159 против 588 Гц; разница уровня около 0.71 дБ. Система не читает один общий popcount. |
| Четыре блинкера: эволюция / замороженное управление | Первые 0.5 с заданы одинаково. На 4–12 с уровень отличается примерно на 0.003 дБ; средний spectral flux 0.01962 против 0.00694. Изменяется временное поведение спектра при практически одинаковом уровне. |

Эти цифры обосновывают передачу кандидата в живой стенд; они не подтверждают слышимость и интересность. В дополнительной 20-секундной пробе поле переносилось туда-обратно каждые 4 с без перезапуска: центроид последних двух секунд участков 2354 → 363 → 249 → 137 → 311 Гц. После первого переноса исходный спектр не восстановился; поздние участки содержат 85–91% энергии ниже 100 Гц. Значит, проблема длительного преобладания низких частот не устранена выбором другого канала. N1 проверит этот кандидат в работе с живым полем; заявлять решённую проблему разнообразия нельзя. Поздние участки повторного общего сдвига частот тоже зависят от истории. Не обещать, что возврат поля вернёт прежний звук; для более сильного вывода о причине позднего режима нужен контроль той же длительности.

Чтение поля в N1 предельно конкретно: восемь прямоугольных областей, число живых клеток в каждой. Перестановки внутри одной области при сохранении числа клеток этот опыт не различает. Следовательно, он проверяет пространственное распределение и его эволюцию, не произвольные различия формы. Деление и насыщение — выбранные Researcher параметры данного опыта, не требования пользователя ко всем будущим методам.
