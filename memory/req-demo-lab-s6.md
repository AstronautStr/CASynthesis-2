# S6 — версии кода и закреплённые опыты

2026-09-13. **Задание разработчику: только S6.** S5 принят. Основа — согласованная политика [основного каталога и локальных опытов](decisions.md#2026-09-06--основной-каталог-и-локальные-опыты); [общий план](req-demo-lab.md).

## Для пользователя — прочитать только это

**Результат:** каталог показывает, какие находки привязаны к сохранённой версии кода, а какие сделаны на локальных изменениях. Закреплённую находку можно продолжить в её исходной версии, если код и подходящее окружение доступны.

«Проверить воспроизводимость» по-прежнему пересчитывает опыт текущим кодом и сравнивает A, B и «как слушал». Сами WAV всегда доступны независимо от возможности запуска. Три ручные проверки — в конце; работу с Git готовит разработчик.

## Поведение каталога

- Один список с двумя понятными статусами: **«Закреплённый»** и **«Локальный»**. В карточке — короткая ревизия либо причина локального статуса, отдельно доступность исходного запуска.
- Save автоматически закрепляет новый опыт, если использованный код достоверно соответствует сохранённой Git-ревизии; иначе сохраняет локально. Несохранённые в Git исследования разрешены.
- Изменения отчётов, заметок и других файлов вне исполняемого набора не делают звук локальным. Запись при непроверяемом происхождении не должна выглядеть закреплённой.
- У локальной записи добавить **«Закрепить»**: после коммита можно подтвердить соответствие её кода этой ревизии. Подробные правила ниже.
- «Слушать запись» работает как прежде. **«Проверить воспроизводимость» использует текущую реализацию**, не переключается незаметно на исходную; сравниваются все три дорожки.
- **«Продолжить» у закреплённой записи использует исходную реализацию.** При совпадении кода и окружения можно остаться в текущем процессе; иначе открывается отдельный стенд сохранённой версии с этой находкой. Показать, какая версия работает.
- Для локальной записи продолжение текущим доступным кодом остаётся возможным по правилам S5, с явным статусом «локальная / текущий код»; отсутствующей исходной реализации не приписывать гарантий.
- «Открыть поле заново» остаётся свежим запуском текущим кодом со ссылкой на источник. Вопрос объединения/скрытия двух кнопок отложен пользователем и в S6 не решается.

## Происхождение исполнения

Добавить в запись версионированное описание источника: идентификатор репозитория, полный commit id (если известен), манифест использованных файлов/ресурсов и их общий отпечаток, состояние проверки соответствия коммиту, версии Python и зависимостей, ОС/архитектура и параметры аудиоконтекста. Версии сторонних библиотек фиксировать точно: нижние границы из нынешнего requirements.txt недостаточны для описания окружения.

**Отпечаток относится к реально исполнявшемуся коду.** Зафиксировать источник при инициализации исполнителя и передавать его в срез записи; не брать новый HEAD только в момент Save. Учесть смену файлов/коммита при уже запущенном приложении и собственный источник подпроцессов. Если доказать соответствие загруженной реализации нельзя, сохранить локально с объяснением; для следующей фиксации предложить перезапуск. Горячую замену модулей не реализовывать.

Для текущего проекта достаточно консервативного явного набора runtime: demo_bench.py, casynth_lab, общие casynth_core/engine/config, описание зависимостей и используемые ресурсы. Список расширяется при подключении зависимостей движка; неизвестный внешний модуль нельзя молча исключить. Не писать универсальный анализатор импортов. Тесты, memory, docs, obsidian, записи каталога и временные результаты в этот набор не входят.

Соответствие коммиту проверяется по содержимому этого набора, включая staged/unstaged и новые runtime-файлы, а не только по общему git status или одному файлу движка. Учесть преобразование переводов строк Git на Windows: сравнивать в согласованном представлении, не получать ложную грязную рабочую копию из-за CRLF. Ревизия и отпечаток содержимого — разные поля.

Окружение описывается отдельно от кода. **«Закреплённый» означает установленное происхождение**, а возможность запуска и совпадение PCM подтверждаются отдельными проверками; один commit id не доказывает весь набор свойств.

## Удержание и запуск исходной версии

Нужные коммиты удерживать постоянными Git-ссылками в отдельном пространстве имён приложения. Не полагаться только на SHA в JSON: коммит должен оставаться доступным после удаления временной ветки и сборки мусора Git. Создание удерживающей ссылки и фиксация статуса согласованы: сбой не оставляет ложный закреплённый статус.

Код в папку каждой находки не архивировать. Для исполнения достаточно кэша отдельных detached checkout/worktree по ревизии. Основной checkout, его ветка, индекс и незакоммиченные изменения не переключаются и не очищаются.

S6 поддерживает **доступный проверенный Python/окружение** с подходящими точными версиями зависимостей и совместимым контекстом. Можно использовать совпадающее существующее окружение. Автоматическая установка старых Python, универсальный менеджер окружений и контейнеры не входят в шаг; при отсутствии подходящего окружения показать причину недоступности.

Добавить минимальный договор запуска стенда/рабочего процесса: абсолютный путь общего каталога, id записи и действие. Подпроцесс импортирует модули выбранного checkout и сообщает фактический отпечаток/окружение; не подтягивает код основного checkout через cwd или пути импорта. Возможность продолжения снимка проверяет **выбранная реализация**, даже если текущий реестр уже не знает этот движок.

Исходный стенд видит тот же каталог; сохранённое из него ответвление появляется в общем списке, получает parent_record_id и происхождение действительно использованной версии. Каталог не должен незаметно создаваться заново внутри кэша worktree. При открытии второго стенда живые синты не звучат одновременно.

Кэш кода можно восстановить из удерживаемого коммита. При повреждении кэша, отсутствии коммита, несовместимом формате снимка или ошибке запуска текущая сессия остаётся доступна, WAV проигрывается, причина отказа видна. Незаметного перехода с исходной версии на текущую не делать.

## Локальные записи и закрепление

- При совпадении зафиксированного отпечатка опыта с подтверждённой ревизией «Закрепить» меняет только сведения о происхождении/статус: id, WAV, исходные условия, журнал и снепшоты прежние.
- При несовпадении закрепление отклоняется с объяснением. Новая реализация может дать **новый связанный опыт** через запуск и Save; старые данные не переписываются.
- Сходство звука и даже совпадение трёх WAV не заменяют доказательства происхождения кода.
- Старые S4/S5 без отпечатка остаются локальными с пометкой «версия кода не зафиксирована». Их не привязывать задним числом к текущему HEAD. Прежние чтение, проигрывание, проверка и допустимое продолжение сохраняются; новые производные опыты получают собственные сведения.
- Слои можно реализовать метаданными или каталогами; существующие id, ссылки родителей и записи форматов 1/2 должны продолжать работать. Не переносить данные массово без необходимости. Целостная запись и сохранность оригиналов остаются требованиями.

## Автоматическая приёмка

1. **Классификация.** В изолированном тестовом репозитории: чистый runtime → закреплённый; изменение общего DSP, staged/unstaged или новый runtime-файл → локальный; правка документа → прежний статус. Проверить Windows checkout с CRLF и несколько используемых модулей.
2. **Источник процесса.** Запустить код X, затем изменить файлы/HEAD на Y и сохранить: результат не приписан Y. Отдельно проверить происхождение расчёта в подпроцессе и нового ответвления.
3. **Закрепление.** Локальный опыт → совпадающий коммит → закрепить: содержимое опыта и id неизменны. Другой код и совпадающий только PCM не дают закрепления. Ошибка Git/метаданных не создаёт ложного успеха.
4. **Исходная версия.** Подготовить две совместимые ревизии с проверяемым различием звука: продолжение закреплённого X из стенда Y действительно исполняет X; проверка воспроизводимости в Y действительно считает Y. Удалить временную ветку и кэш, запустить Git gc в тестовом репозитории: удержанный X восстанавливается и запускается.
5. **Каталог и совместимость.** Ветка из исходного стенда сохраняется в общий каталог с правильной версией и родителем. Старые записи читаются; при отсутствующих коде/окружении/движке WAV доступен и ошибка конкретна. Основной checkout, индекс и локальные изменения не изменены.
6. **Гейты.** Подключить новые проверки к check.py; старые проверки и эталоны проходят. Изоляция репозиториев и управляемых сбоев — только в тестовых папках; не переписывать рабочую историю проекта для испытаний.

## Сдача и ручная приёмка

Developer готовит рабочий запуск, два небольших демонстрационных опыта (локальный и закреплённый другой доступной версии), обновляет README/current.md/лог. Исходные ревизии и окружение для демонстрации подготовлены заранее; пользователь не выполняет Git-команды.

1. Сохранить обычный опыт из подготовленного чистого запуска — в каталоге есть статус «Закреплённый» и версия.
2. Открыть подготовленный локальный опыт — статус «Локальный», запись прослушивается.
3. У подготовленной находки другой версии нажать «Продолжить» — открывается её исходный стенд с видимой версией и работающим звуком.

Отчёт до десяти строк. Массовая проверка изменившихся опытов — S7; автоматическую разведку, новые движки и отложенный UX двух кнопок не включать. После S6 остановиться для приёмки.
