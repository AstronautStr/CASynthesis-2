# S1 — первое живое демо

2026-09-07. **S1 принят пользователем 2026-09-08**, включая добавленный полный Stop. Ниже — исходное ТЗ принятого спринта. Текущая задача — [S2](req-demo-lab-s2.md) по [общему ТЗ](req-demo-lab.md).

## Для пользователя: приёмка за 2–3 минуты

Разработчик предоставляет один готовый способ запуска. После автоматической приёмки:
1. Нажать **«Запуск»**: видно изменяющееся поле и слышен звук.
2. Нажать **«Пауза КА»**, порисовать/постирать: поле само не эволюционирует, правки применяются, звуковой процесс продолжает работать.
3. Нажать **«Сначала»**: возвращается исходная сцена и воспроизведение начинается заново.

Не нужно оценивать богатство Laplace, сравнивать WAV вручную или вычитывать устройство программы. Достаточно сообщить, какой из трёх пунктов неудобен или не работает.

## Поставка и границы

- Новое отдельное окно: поле, название демо, три кнопки выше, громкость, номер поколения, состояние аудиовыхода. ЛКМ рисует, ПКМ стирает. Старт — без звука и эволюции; «Запуск» запускает оба процесса. «Пауза КА» переключает только эволюцию; после снятия паузы нет догоняющих поколений. «Сначала» сбрасывает поле, часы и весь звуковой хвост и запускает сцену.
- Точки входа: `python demo_bench.py --demo demos/laplace_basic.json`; тот же вход с `--render artifacts/s1.wav --seconds 8` работает без окна и аудиоустройства. Подготовить `run_demo_bench.bat` с разрешённым при настройке путём к проектному Python; не заставлять пользователя ставить пакеты вручную.
- Новые файлы: `demo_bench.py` — UI/CLI; небольшой пакет `casynth_lab/` — исполнитель и адаптер Laplace; `demos/laplace_basic.json` — сцена; тесты S1; минимальный манифест зависимостей/инструкция запуска. Внутреннее разбиение пакета выбирает разработчик.
- В S1 нет A/B, новых методов, каталога, сохранённых сессий, checkpoint, MIDI/DAW, редактора демопакетов и графа. Основной синт и старые стенды не переделывать. Модули DSP подключаются импортом; необходимое общее изменение обосновать узко, без смены существующего звука.

## Одна точная сцена

JSON v1 содержит `id`, `title`, размер поля, координаты живых клеток, правило/границы, скорость, `engine_id`, полный набор параметров движка, настройки звука. Неизвестный движок/параметр и неверные координаты дают понятную ошибку, а не молчаливый fallback.

- Поле 32×32, Conway B3/S23, тор; координаты (строка, столбец): `[(14,15),(14,16),(15,14),(15,15),(16,15)]` — R-pentomino.
- 4 поколения/с; первое поколение наступает через 0.25 с после запуска, до него звучит исходное поле. После шага или правки пересчитывать возбуждение и анализ.
- `engine_id=laplacian`; `n=12, spread=0, alpha=1, shape=0, harm=0, fullshape=1, dyn=0`; опорная и звучащая частота 220 Гц, без изменения высоты.
- Использовать `SR`, `CHUNK_S`, `MASTER_GAIN`, `VOL_DEFAULT` из `casynth_config`; два одинаковых выходных канала (панорама голосов 0.5). GEN-параметры из `GEN_*_DEFAULT`, перевод долей поколения в блоки как в актуальном синте; `amp_slew=False`. VOICE постоянно открыт, tune выключен. Эти разрешённые упрощения фиксируют режим S1; паритет со всеми режимами основного синта не обещается.

## Требования к реализации

1. Общий исполнитель хранит поле, возбуждение, часы, SlotPool, фазы, текущие амплитуды/панораму и gain. UI и офлайн используют один метод получения следующего аудиоблока. Вычисления `step → events_field → analyse → SlotPool.update → render_chunk_laplacian` берутся из `casynth_engine`; `SlotPool.update` вызывается каждый аудиоблок, анализ — при изменении поля.
2. Время определяется фактическим числом рассчитанных сэмплов / SR, не FPS и не номинальным CHUNK_S, округлённым независимо от длины блока. События применяются на первой границе блока не раньше заданного времени; их фактическое время и порядок сохраняются в журнале в памяти. Постоянного хранения этого журнала пока нет. При паузе КА его часы замораживаются, звуковые продолжаются.
3. UI передаёт команды через очередь, расчёт владеет изменяемым состоянием; UI получает копию поля. Аудиоколбэк только читает готовые блоки. Рисование или медленный кадр UI не должны менять темп расчёта. Изменение уровня использует имеющееся сглаживание gain.
4. Офлайн-рендер обрезается до заданной длины в сэмплах, без нормировки. Проверка live/offline сравнивает PCM до транспортного mute/fade аудиоустройства. Для старта/перезапуска допускается короткий явно отделённый транспортный fade; старые очереди звука сбрасываются.
5. Нет аудиоустройства / underrun / клиппинг — видимое состояние и диагностический счётчик. Офлайн не зависит от sounddevice/Pygame. Не показывать успешную аудиоработу при беззвучном fallback.

Не вводить заранее универсальную систему плагинов: S1 оставляет границу «состояние + события → аудиоблок», а реальное расширение договора проверяется новым движком в S3.

## Автоматическая приёмка — разработчик выполняет до передачи

- **Повтор:** два рендера одной сцены и рендер после reset дают одинаковый PCM; проверка на 8 с, без NaN и клиппинга на штатной сцене. Если её заданный уровень клиппирует, уменьшить постоянный уровень только этой сцены, зафиксировать значение; не менять DSP/общие дефолты и не добавлять компрессор.
- **События:** один фиксированный сценарий через очередь живого исполнителя с тестовым аудиоприёмником и через офлайн даёт одинаковые PCM и финальное поле. Включить паузу на 1 с, правку одной клетки, возобновление и изменение уровня; разная частота обновления UI результат не меняет.
- **Часы и reset:** темп соответствует числу сэмплов с точностью одной границы блока; пауза не накапливает шаги; reset сбрасывает фазы/хвосты и очередь. Пустое поле после завершения хвостов молчит, непустая контрольная сцена не молчит.
- **Интерфейс:** headless-smoke запуска и трёх кнопок, рисования обеими кнопками мыши; неверный JSON и отсутствие устройства дают ожидаемое сообщение. Проверить, что выход именно стерео.
- **Регрессии:** `python check.py` проходит в подготовленном окружении; существующие эталоны не обновлять ради прохождения. Сначала установить исходный статус. Известное отсутствие SciPy/Pygame в bundled Python — задача настройки окружения, не задача пользователя.

Артефакты проверок — в `artifacts/`. Сдача: запускаемый S1, краткий список результатов автоматических проверок и три пункта для пользователя в начале этого файла. **После сдачи остановиться на S1.**
