# REQ — Единый Laplace-движок: артикуляция × озвучивание

2026-09-21. **Заказ пользователя, инженерная постановка для Developer.** Продолжение
[ТЗ по шву](req-seam-2026-09-21.md); начинать **только после того, как шов сдан** (все
семь коммитов A1–B2, `check.py` зелёный, `verify` по каталогам — `exact`).

Повод — прямое требование пользователя: «я ТОЧНО хочу использовать Events вместе с фм и
вейвтейблом. фм и вейвтейбл можно разделить — это будет два режима, табличный с синусом
(которая по сути обычный лаплас движок) и еще + пила и меандр; второй режим — фм».

Сегодня это невозможно. Четыре движка (`laplacian`, `laplace_carriers`, `laplace_fm`,
`ca_object_resonators`) — монолиты, где затухающая мода **и есть** осциллятор
(`object_resonators.py:572`, ядро `_render`). Комбинировать их нечем: сочетаний
«Events + пила» и «Events + ФМ» просто не существует как кода.

## 1. Что делаем

Разрезаем по слоям и собираем **один** движок:

```
поле → фигуры (тор, трекинг) → моды (f_j, phi_j, pan)
   ↓
артикуляция:  Env | Events                  → траектория a_j(t)
   ↓
озвучивание:  Bank(Sine|Saw|Square) | FM    → сэмплы
   ↓
выход: пан, глайд гейна, клип, метр          (общий хвост)
```

**Математическое основание разреза.** В ядре мода живёт как
`z ← r·e^{iω}·z + удар` (`object_resonators.py:670-676`), и звучит `Re(z)`
(`:676`, `acc += wcur[s,j] * nre`). Значит **между ударами** мода — это ровно
`a₀·rⁿ·cos(ωn + φ₀)`: и амплитуда, и фаза известны в замкнутой форме. Поэтому «затухание»
можно отдать отдельным слоем как траекторию амплитуды, а озвучивать её потом чем угодно —
синусом, таблицей или индексом ФМ. Комбинаторного взрыва движков не будет.

## 2. Оси и ручки

| Ручка | Значения | Дефолт | Видна |
|---|---|---|---|
| `n`, `spread`, `alpha`, `shape`, `harm`, `fullshape`, `dyn` | как сейчас | как сейчас | всегда |
| `artic` | Env / Events | **Env** | всегда |
| `voice` | Bank / FM | **Bank** | всегда |
| `wave` | Sine / Saw / Square | **Sine** | при `voice = Bank` |
| `FM d` | 0.0 .. 4.0 | 1.0 | при `voice = FM` |
| `ev` | Both / Births / Deaths | Both | при `artic = Events` |
| `rad` | 0.25 .. 4.0 | 1.0 | при `artic = Events` |
| `dec` | 0.20 .. 1.50 s | 0.80 | при `artic = Events` |
| `atk` | 0 .. 20 ms | 0.0 | при `artic = Events` |

Семь спектральных параметров действуют во **всех** клетках и идут первыми — они самые
«сквозные». Неактивные ручки в панели не рисуются (метаданные `inactive`, механика из A4
ТЗ по шву). Максимум видимых строк: `Env+Bank` — 9, `Events+FM` — 13.

`FM d = 0` — это **синус на f0**, а не возврат к baseline; фигура без ненулевых мод молчит
при любой глубине. Смысл нуля обязан быть написан рядом с ручкой
([req-laplace-fm](req-laplace-fm-2026-09-20.md) §2).

## 3. Байтовые якоря — каждый уже существует как гейт

Единый движок не «надо доказать, что он такой же» — он обязан пройти уже написанные гейты.

| Клетка | Эквивалент | Гейт |
|---|---|---|
| `Env + Bank + Sine` | нынешний `laplacian` | `tests/golden/golden_master.py`, `test_laplace_carriers.py::test_bank_sine_is_the_baseline_byte_exact` |
| `Env + Bank + Saw/Square` | `Laplace waves` (Wave bank) | `test_laplace_carriers.py` (34 теста, гейт `1r`) |
| `Env + FM` | `Laplace FM` | `test_laplace_fm.py` (43 теста, гейт `1s`) |
| `Events + Bank + Sine` | `Objects` (Disk / Laplace / Fixed) | `1l`–`1q`: `test_n4_object_resonators.py`, `test_objects_laplace.py`, `test_objects_radius_attack.py`, `test_objects_event_source.py`, `test_objects_decay.py` |
| **`Events + Bank + Saw/Square`** | **новое, эталона нет** | §6 |
| **`Events + FM`** | **новое, эталона нет** | §6 |

**Ключ к дешевизне: закон Objects не переписывается.** Для клетки `Events + Bank + Sine`
переиспользуется **само ядро** `object_resonators._render` — тогда байт-равенство
тривиально, и пять гейтов Objects переблессивать **не нужно**. Для остальных клеток
артикуляция Events отдаёт наружу `(f_j, a_j(t), φ_j)` — величины из §1, известные в
замкнутой форме между ударами, — а озвучивает их таблица или ФМ.

Если байт-равенство какой-либо из первых четырёх клеток не достигается — **это стоп, а не
повод блессить**. Гейты закона не переписываются.

## 4. Что берём из Objects и что не берём

**Берём:** трекинг фигур (`figures.components:64` — 8-связность через шов тора,
`figures.match:296` — сопоставление между полями), маску **Disk** (`figures.disk_mask:170`,
радиус `radius_mul · R`), закон пакета `_strike:1253` (`a = e/(e + EVENT_SAT)`,
`EVENT_SAT = 2.0`, `event_network.py:69`), `_track:1317` (`births = G & ~G_prev`,
`deaths = G_prev & ~G`, `e = e_b + e_d` для Both / `e_b` для Births / `e_d` для Deaths),
затухание **Fixed** (`gamma = ln(1000)/T60`), атаку.

**Не берём** (решение пользователя): селектор `decay_law` Common / Modal age (v6, возрасты
клеток — `T_FRESH_S`, `AGE_TAU_S`, `gam_a/gam_t` в ядре `:655-660`); `excitation` /
Birth position (`birth_position_weights:516`, v5); `birth_strength`
(`birth_strength_profile:548`); детектор **Own**; спектр **Figure** (спектр всегда Laplace);
`frequency_scale` — его роль в прототипе играют `ctx.f0` и `transpose`.

**Законы, которые нельзя нарушить** (из принятых REQ):
- Births и Deaths — **положительные** события; смерть никогда не превращается в
  отрицательный импульс. Deaths считаются по **предыдущей** маске; появление банка при
  Deaths события не создаёт ([req-objects-event-source-modal](req-objects-event-source-modal-2026-09-17.md) §1-2).
- Переключение селектора само по себе импульса не создаёт.
- `dyn` — отдельный канал спектральных весов, **не** часть селектора Events. Не сливать.
- ФМ: `β_j = I·a_j` в **радианах**, без нормировки на число мод, на Σa и на RMS; одна
  несущая на `f0`; все моды в одну фазу; взаимной модуляции, каскадов и feedback нет;
  фиксированный DC-блокер `r = exp(−2π·5/sr)` без ручки
  ([req-laplace-fm](req-laplace-fm-2026-09-20.md) §2-4).
- Волны: `c_h` — Sine 1 при h=1, Saw `1/h`, Square `1/h` по нечётным; полоса `b(ν)` считается
  по частоте **каждой волны**, не по f0; никаких `sign(sin)`, независимых фаз гармоник и
  нормировки каждой волны на peak/RMS
  ([req-laplace-carriers](req-laplace-carriers-2026-09-20.md) §3).

**Сегментация на торе — только внутри `artic = Events`.** Вне её путь остаётся прежним
(`casynth_engine.analyse:133`, `ndimage.label` без учёта замыкания). Пользователь:
«давай сначала напиши так, чтобы только в режиме события оно работало тором… тогда тор
отдельно доделаем и поправим золото». Сделать тор общим поведением и переснять эталон —
отдельная задача **после** этой.

## 5. Старые id — алиасы

Решение пользователя: «схлопнуть, старые — алиасы».

`laplacian`, `laplace_carriers`, `laplace_fm`, `ca_object_resonators` остаются в реестре как
алиасы единого движка с **зафиксированными** значениями осей:

| id | `artic` | `voice` | прочее |
|---|---|---|---|
| `laplacian` | Env | Bank | `wave = Sine` |
| `laplace_carriers` | Env | Bank / FM по `method` | ветка Filter — см. ниже |
| `laplace_fm` | Env | FM | — |
| `ca_object_resonators` | Events | Bank | `wave = Sine` |

Требование: сцены `demos/*.json`, снапшоты (`STATE_VERSION`, `COMPATIBLE_STATES`) и записи
`lab_catalog/` продолжают воспроизводиться **байт-в-байт**. Это и есть гейт этапа:
`python -m casynth_lab.verify lab_catalog/<root>` по всем каталогам — все дорожки `exact`.

Ветка **Filter** из `laplace_carriers` (`method = Filter`, `filter_width_oct`,
`filter_depth_db`, `_FilterVoices:339-470`) в оси единого движка не выводится, но обязана
продолжать работать под своим алиасом — у неё есть записи в каталоге. В панель прототипа её
не выводить (решение пользователя: «только Wave bank»).

## 6. Новые клетки — отдельным шагом, через пайплайн

`Events × Saw`, `Events × Square`, `Events × FM` ни в одном REQ не описаны. Затухающий
`a_j` в ФМ даёт затухающий индекс — классическая ФМ-перкуссия; это ожидаемо музыкально
интересно, но это **новый закон**, а не следствие старого.

По конвенции проекта (`CLAUDE.md`, [пайплайн](research/listening-experiment-pipeline.md))
новый слуховой опыт требует нетривиального вопроса и решения, которое ответ может изменить.
Developer **не изобретает дополнительные слуховые кейсы сам**: реализует клетки, закрывает
их гейтами закона (не байтовыми — эталона нет), и передаёт Researcher для постановки опыта.

Минимальные гейты для новых клеток:
- `Events × Bank × Saw` при `dec → ∞` сходится к `Env × Bank × Saw` в пределах допуска;
- `Events × FM` при `FM d = 0` даёт затухающий синус на `f0` с масштабом `A_object`;
- `β` остаётся в радианах и ни на что не делится; нет энергии выше `0.40·sr`; DC-блокер
  на месте;
- переключение любой оси само по себе не создаёт импульса и не даёт разрыва.

## 8. Когда звать пользователя

Только пары `differs` из отчёта `casynth_lab.verify`, и только с вопросом **«биты разошлись,
характер звучания тот же?»**. Пакет собирается автоматически:
`<root>/.verify/<run_id>/<record_id>/<track>.wav` рядом со старым, слуховая отметка отдельно
от байтового вердикта (`marks.json`), и по докстрингу `verify.py:21-23` малое численное
расхождение **никогда** не помечается «неслышимым» само.

`exact` до пользователя не доходит. Пользователь ручным тестировщиком не работает. Новый
слуховой опыт по клеткам из §6 — другой канал, через Researcher и пайплайн.

## 9. Риски и что согласовать

- **Перформанс.** Замерено при бюджете чанка 8.0 мс: синусный банк на 480 живых слотах —
  7.23 мс, на 960 — 14.16 мс; ФМ при 24 фигурах × 20 мод — 10.94 мс. Клетки — альтернативы,
  а не надстройки (в Events синусный банк не работает вообще), но запаса нет ни у одной.
  Починка отложена пользователем на следующую итерацию; индикатор мс/чанк и андерранов
  появляется в B2 ТЗ по шву. **Сверки идут оффлайн-рендером и к просадкам CPU неуязвимы.**
- **Волновая таблица и транспозиция.** Стендовый `wavetable` (`laplace_carriers.py:157-174`)
  кэшируется по **точной** частоте, а в прототипе звучит `freq · transpose`: смена ноты даёт
  480 промахов по 59 мкс = 28 мс, и кэш на 256 записей трэшится каждый блок. Рабочий ключ —
  **число гармоник** `k = len(harmonic_indices(waveform, f))`: множество гармоник внутри
  ячейки точное, таблиц выходит 50–80 вместо 480, 3–5 МБ. Цена — косинусный тейпер полосы
  заменяется брикволом при `0.45·sr`. Это **отклонение от закона REQ ⇒ ревью Researcher до
  реализации**; запасной вариант той же строкой: `k0 = floor(0.40·sr/f)` (закон не
  переопределяется, только усекается). Сетка частот по полутонам **не подходит**: −25 дБ
  ошибки, а при малом `k` таблица пустеет и мода замолкает.
- **Векторизация.** Скалярный `table_wave` по слотам — +4.7 мс к 7.2, не проходит. Ветка
  Saw/Square обязана быть векторной (flat-index в плоский `(K·8192,)` массив: 7.37 мс при
  480 слотах — паритет с синусом). Синусную ветку векторизовать **нельзя**: изменится
  порядок суммирования и поедут биты.
- Правки `casynth_core.py` (реестр, алиасы) — ревью Researcher.
- Порог «мода не изменилась» 0.01 Гц для модуляторов ФМ — вопрос открыт с 2026-09-21
  (`memory/questions.md`), в одиночку не менять.
- Сочетание `Events × Filter` не определено и не заказано — не делать.
