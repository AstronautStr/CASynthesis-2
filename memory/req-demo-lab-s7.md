## Для пользователя — прочитать только это

**Результат:** запускаешь проверку каталога, получаешь список отличий и слушаешь «сохранённое / пересчитанное» без потери позиции. Стенд проверяет все три дорожки каждого опыта; численное отличие и твоя оценка на слух хранятся отдельно.

**Приёмка:** три действия на подготовленных записях, до трёх минут. Кнопки «Продолжить» / «Начать заново» пока остаются как есть.

## 1. Один запуск → сохранённый отчёт

- В каталоге добавить действие **«Проверить каталог»**: последовательно пересчитать все записи, которые были в каталоге на старте. Включать закреплённые, локальные и старые записи. Новые записи попадут в следующий запуск. Пустой каталог — понятное сообщение.
- Это автоматическая обработка после одного явного запуска. Фоновый наблюдатель за Git, запуск при каждом открытии приложения и выбор произвольной пары ревизий не нужны в S7.
- Показать версию проверяющего кода, прогресс «N из M», текущую запись и отмену. Интерфейс остаётся отзывчивым. Одновременно выполняется одна проверка; не запускать конкурирующую одиночную проверку или второй рабочий процесс из этого стенда.
- Ошибка одной записи не останавливает остальные. Отмена прекращает дальнейшую работу, сохраняет завершённые результаты и явно отмечает непроверенные записи. Долгая отдельная запись тоже отменяется; автоматическое возобновление после перезапуска не требуется.
- Отчёт доступен после закрытия приложения. По умолчанию показать отличия, по одной записи для прослушивания; рядом — количества точных совпадений и непроверенных. Эти группы тоже можно открыть. Пользователь не обязан оценивать весь список.

## 2. Что именно пересчитываем

Использовать существующий путь `Catalog.replay` / `DemoRunner`, расширив его для S7. **Не создавать второй алгоритм воспроизведения журнала.**

- Восстановить исходные условия опыта и применить записанные действия текущим кодом. Для ветки началом служит её исходный снепшот; для обычного опыта — начальные условия. Конечное поле не подменяет начало опыта.
- Рассчитать всю необходимую предысторию, но сравнивать ровно сохранённое окно `audio_start_sample … end_sample`: **A, B и monitor («как слушал»)**, каждую дорожку со своей оригинальной записью.
- Сохранять параметры, времена событий и поведение переключения A/B из опыта. Не подставлять новые дефолты, не нормировать громкость, не подгонять временной сдвиг или частоту дискретизации ради совпадения.
- Если текущая реализация не понимает движок, параметр, формат исходного снепшота или контекст рендера, результат — «Не удалось проверить» с причиной. Не заменять точное восстановление новым запуском из поля.
- Исходный код опыта для этой операции запускать не нужно: эталон — сохранённый WAV. Отсутствие старой Git-ревизии само по себе не мешает проверке текущим кодом. Продолжение в исходной версии остаётся отдельной возможностью S6.

## 3. Происхождение и хранение результата

- У запуска единая целевая реализация: фактически исполняемый код рабочего процесса и его окружение. Зафиксировать происхождение средствами S6 при старте; показать commit либо локальный статус с отпечатком. Не приписывать рабочему процессу версию старого открытого окна или HEAD на момент завершения.
- Разрешить проверку незакоммиченной реализации: отчёт явно локальный. Обнаруженное изменение исполняемого набора во время работы не должно смешивать версии в одном отчёте: остановить запуск, незавершённый результат считать непроверенным, уже достоверно завершённые сохранить. Способ организации процесса выбирает Developer; дополнительное хранилище копий локального кода не требуется.
- Хранить отдельный отчёт запуска: ID, время, целевое происхождение и окружение, состав записей, завершённость; для каждой записи — ID, исходное происхождение, отпечатки использованных условий/снепшотов/PCM, результаты дорожек и причины ошибок. Отсутствующие сведения старых записей оставить неизвестными.
- Новые WAV отличающихся дорожек сохранять вместе с результатом. Для точно совпавших достаточно проверки и отпечатка оригинала. Просмотр готового отчёта не запускает рендер заново.
- Исходные WAV, состояния, журнал, привязка к Git и родительские связи опыта неизменны. Повторная проверка создаёт новый отчёт. Нынешний перезаписываемый каталог `<record>/replay/` не может быть единственным хранилищем S7: следующая одиночная проверка не должна испортить готовую пару.
- Отчёт всегда называет проверенную версию; после изменения кода старый отчёт не становится проверкой «текущей версии». Утрата или подмена файлов пары обнаруживается по отпечаткам и не оставляет действительным прежний вывод.

## 4. Машинный результат и оценка на слух

Для **каждой дорожки** хранить один из результатов:

| Результат | Основание |
|---|---|
| Точное совпадение | Совпали формат, длина и все PCM-сэмплы; различия заголовков WAV сами по себе несущественны |
| Численно отличается | Получена сопоставимая пара PCM, есть отличия сэмплов или длины |
| Не удалось проверить | Нет валидной пары; конкретная причина |
| Не проверено | До записи не дошли, запуск отменён или потеряна достоверность целевой версии |

В карточке показывать результаты A/B/monitor по отдельности: совпадение только monitor не означает совпадения всего опыта. Частичный сбой не скрывает уже полученные результаты остальных дорожек.

Для одинакового формата и длины достаточно двух диагностик в раскрываемых подробностях: доля отличающихся сэмплов и максимальная абсолютная разность в единицах PCM. Разность считать без переполнения int16. Несовпадение длины показывать отдельно; не обрезать хвост для объявления совпадения.

**Малое численное отличие не получает автоматический ярлык «не слышно» или «характер сохранён».** Рядом с прослушиванием дать необязательную отметку «Не слышу разницы» / «Слышу разницу», с возможностью вернуть «Не оценено». Отметка относится к конкретной паре рендеров и дорожке, переживает перезапуск и не переносится на новый отчёт. Она не отменяет машинный результат. Решение о major-версии, замене эталона или необходимости старой версии автоматически не принимать.

## 5. Слушать пару без путаницы с A/B опыта

- Выбор дорожки: **A / B / Как слушал**. Независимый переключатель версии: **Сохранённое / Пересчитанное**. Не обозначать версии ещё одной парой A/B.
- При открытии отличающейся записи выбрать изменившийся monitor, а если он совпал — первую изменившуюся дорожку A/B. Пользователь сразу попадает на отличие, а остальные результаты видны рядом.
- Одна позиция воспроизведения для обеих версий. Переключение версии продолжает с того же сэмпла, а не перезапускает файл. Достаточно Play/Stop и переключения; таймлайн и монтаж не входят в S7.
- Громкость воспроизведения общая, автоматического выравнивания нет. Короткое сглаживание переключения допустимо только в плеере; оно не меняет сравниваемый PCM. Живой синт не подмешивается.
- При разной длине показать расхождение; обе версии идут по общей позиции, после конца короткой — тишина. Не растягивать и не скрывать несовпавший хвост. Пара с несовместимым аудиоформатом не считается готовой для синхронного переключения.

## 6. Автоматическая приёмка Developer

Добавить проверки в общий `check.py`, используя изолированные каталоги/репозитории и существующие фикстуры:

1. Совпавший опыт; отличие только A при совпавших B/monitor; отличие только monitor; одиночная разница в 1 PCM-единицу; тишина; крайние значения int16; разная длина. Проверить классификацию и диагностики, без вывода о слышимости.
2. Обычный опыт с предысторией длиннее сохранённого окна и ветка от снепшота с вмешательствами/переключениями: одиночный и пакетный пути дают одинаковый PCM всех трёх дорожек.
3. Локальный/старый опыт, отсутствующий исходный commit, неподдерживаемый снепшот, повреждённый WAV: доступные записи проверяются, ошибки имеют причины, исходники каталога неизменны.
4. Происхождение целевого процесса, изменение runtime между элементами очереди, отмена внутри долгой записи, частичная ошибка: нет ложного полного успеха и смешения версий. Отдельная проверка не перезаписывает готовую пару; повторный запуск и перезапуск приложения сохраняют прежний отчёт и слуховую отметку.
5. Общий курсор плеера и переключение версии на ожидаемый сэмпл, одинаковый gain, отсутствие живой примеси, конец короткой дорожки. Проверять PCM/позиции через тестовый вывод без участия пользователя.

Прогнать `check.py`; прежние аудиоэталоны сохраняются. Подготовить небольшой отдельный демонстрационный каталог с точным совпадением, заметным отличием и недоступным для пересчёта опытом. Использовать существующий движок и контролируемую тестовую ревизию; не менять рабочий DSP ради демонстрации и не просить пользователя готовить Git или портить свои записи.

## Три ручных шага — до трёх минут

1. В подготовленном каталоге нажать «Проверить каталог»: дождаться короткого отчёта, увидеть совпадение, отличие и понятную причину недоступности.
2. Открыть готовое отличие и послушать 10–15 секунд, переключая «Сохранённое / Пересчитанное»: версия меняется, ход фразы продолжается. Поставить слуховую отметку.
3. Переоткрыть стенд: отчёт, пара и отметка доступны без пересчёта; исходную запись можно слушать как прежде.

**Граница:** только проверка существующих опытов и прослушивание результатов. S8–S10, новые движки, автоматический выбор художественно лучших звуков, разбор двух кнопок и перевод интерфейса на другой UI-пакет не входят. После сдачи остановиться для приёмки.
